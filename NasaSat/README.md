## ส่วนที่ 1 — สำหรับคนในทีม (อ่าน 3 นาที)

### โอเค ตอนนี้เรามี 4 อย่าง

| | อะไร | อยู่ไหน | เอาไว้ทำอะไร |
|---|---|---|---|
| 1 | **โค้ดบอร์ด (firmware)** | `firmware/NasaSat/NasaSat.ino` | เปิดใน Arduino IDE แล้วอัปโหลดลง ESP32-S3: บอร์ดหาแสง หมุนตัวดาวเทียมหันเข้าหาแสง และถ่ายภาพได้ |
| 2 | **เว็บ tool "NasaSat Lab"** | `tool/NasaSatLab.html` | ดับเบิลคลิกเปิดใน Chrome/Edge (ไม่ต้องติดตั้ง ไม่ต้องมีเน็ต) ใช้ต่อบอร์ด คาลิเบรต สั่งภารกิจ ดูกราฟ ดูภาพ และมี**ตัวจำลอง**ให้ซ้อมโดยไม่มีบอร์ด |
| 3 | **เอกสาร** | `docs/` | ทฤษฎีทั้งหมดไว้ตอบกรรมการ (THEORY), คู่มือวันแข่ง (PLAYBOOK), สรุป 1 หน้า (CHEATSHEET) มี PDF พร้อมพิมพ์ |
| 4 | **ระบบทดสอบ + ผลตรวจ** | `firmware/host_test/`, `review/` | ทดสอบโค้ดบอร์ดตัวจริงบนคอมกับโลกจำลอง ผ่านหมดทุกข้อ, compile กับ ESP32 ของจริงผ่าน, บันทึกว่าตรวจเจออะไรและแก้อะไรไปแล้ว |

แถม: `firmware/Fallback/Fallback.ino` โค้ดสำรองไฟล์เดียว (ทำภารกิจ 1 อย่างเดียว) ใช้ตอนตัวหลักพังจริง ๆ

### มันทำงานคร่าว ๆ แบบนี้

```
หลอดไฟ ──► LDR 2 ตัว วางเอียงเป็นตัว V ──► บอร์ดดูว่าฝั่งไหนสว่างกว่า ──► คิดเป็นมุมแสง θ
                                                                   │
   ภารกิจ 1: มอเตอร์ stepper หมุนตัวดาวเทียมจน θ = 0 (หันตรงหลอด) แล้วค้างไว้
   ภารกิจ 2: รู้ทิศหลอด ("ดวงอาทิตย์") แล้ว → หมุนไปมุมเป้า → ถ่ายภาพ → ส่งภาพเข้าคอม
```

- LDR ซ้ายสว่างกว่าขวา = หลอดอยู่ทางซ้าย, สว่างเท่ากัน = หันตรงพอดี
- ก่อนใช้ต้อง **คาลิเบรต** (~10 นาที) คือสอนบอร์ดว่าค่าแสงแบบนี้ = มุมเท่าไร เว็บพาทำทีละขั้น 8 ขั้น
- ค่าทุกอย่าง (ขา, ความเร็ว, เกณฑ์) แก้จากเว็บได้เลยโดยไม่ต้องอัปโหลดโค้ดใหม่ แล้วกด SAVE เก็บไว้ในบอร์ด

### วันแข่งทำอะไร (ย่อสุด ๆ)

1. อัปโหลด firmware (ปิด Serial Monitor และกด "ตัดการเชื่อมต่อ" ในเว็บก่อน)
2. เปิดเว็บ → เชื่อมต่อ → ฮาร์ดแวร์ (อ่านรายงานชิป, หาขา LDR)
3. คาลิเบรต 8 ขั้น → ตั้งศูนย์กับของอ้างอิงจริง (ท่อเล็ง/เลเซอร์)
4. ภารกิจ 1 กด "เริ่ม" → ภารกิจ 2 กด "หันไปที่เป้าแล้วถ่าย"
5. ฉุกเฉิน: **STOP** = ปุ่มแดงมุมขวาบน หรือกด Space / Esc

ละเอียด: `docs/PLAYBOOK_TH.pdf` (แผนรายวัน + checklist + ผังแก้ปัญหา) และ `docs/CHEATSHEET_TH.pdf` (พิมพ์วางข้างคีย์บอร์ด)

### เรื่องที่ต้องรู้ (สำคัญ)

- **ยังไม่เคยลองกับบอร์ดจริงเลย** ทุกอย่างผ่านในโลกจำลองบนคอม + compile กับ ESP32 ของจริงผ่าน ต้องหาชุดซ้อม (ESP32-S3 + มอเตอร์ 28BYJ-48 + ULN2003 + LDR) มาลองให้เร็วที่สุด
- ตัวเลขความแม่น (เช่น 0.04°) เป็น **ผลจากโลกจำลอง** ก่อนพูดกับกรรมการต้องวัดของจริงก่อน
- ยังไม่ได้ทำ Wi-Fi / ESP-NOW รอดูว่าผู้จัดใช้สถานีภาคพื้นแบบไหน (อบรม 6 ต.ค.)
- พก `tool/NasaSatLab_v1_backup.html` (หน้าเว็บแบบเก่า ใช้ได้ครบ) ไปด้วย เผื่อหน้าใหม่มีปัญหา

## ส่วนที่ 2 — เว็บ tool ของเรา: NasaSat Lab

- **เปิด**: ดับเบิลคลิก `tool/NasaSatLab.html` ด้วย **Chrome หรือ Edge** (ต้องใช้ Web Serial ต่อ USB) ไฟล์เดียวจบ ทำงานออฟไลน์ ฟอนต์ฝังในไฟล์แล้ว
- **ซ้อมไม่มีบอร์ด**: หน้า "เชื่อมต่อ" เลือก "ตัวจำลอง" (หรือเปิด `NasaSatLab.html#sim`) ตัวจำลองทำงานกติกาเดียวกับบอร์ดจริง และปรับหลอด แสงห้อง noise backlash กล้องได้
- **ข้อห้าม**: ก่อนกด Upload ใน Arduino IDE ต้องกด "ตัดการเชื่อมต่อ" ก่อน และห้ามเปิด Serial Monitor พร้อมกัน (พอร์ตใช้ได้ทีละโปรแกรม)

### หน้าจอ

- **แถบบน (เห็นตลอด)**: มีช่องเรียงกันดังนี้
  - ช่องทาง: ป้ายสีฟ้าอมเขียว = ตัวจำลอง ไม่ใช่บอร์ดจริง
  - ภารกิจ 1: พัก / ค้นหาแสง / กำลังปรับ / ล็อกแล้ว / หาแสงไม่เจอ
  - งานที่บอร์ดกำลังทำ
  - **θ มุมแสง** ตัวใหญ่
  - error ภารกิจ 1
  - มุมตัวขับ
  - แสงที่เซนเซอร์: เห็นแสง / ไม่เห็นแสง / ADC ตัน
  - ป้าย **"ยังไม่ SAVE n"**: กดแล้ว SAVE ให้
  - ป้าย **"ปัญหา n"**: เปิดรายการ error พร้อมวิธีแก้เป็นภาษาไทย ค้างอยู่จนกด "รับทราบ"
  - ปุ่มคัดลอกให้ AI, สลับธีมสว่าง/มืด และ **STOP**
- **เมนูซ้าย**: "ลำดับวันแข่ง" 1–5 เรียงตามที่ทำจริง (สี่เหลี่ยมเขียวท้ายชื่อ = ทำแล้ว) และ "เครื่องมือ"
- **Console ล่างสุด**: พับไว้ เห็นบรรทัดล่าสุดกับจำนวน error และพิมพ์คำสั่งได้เลย (↑/↓ เรียกคำสั่งเก่า) กด "Console" เพื่อขยาย ติ๊ก "เฉพาะ error" เพื่อกรอง
- ปุ่มที่ส่งคำสั่งเข้าบอร์ดมี **ชื่อคำสั่งต่อท้าย** เช่น `วัดแสงรอบข้าง │ AMB 600` เอาไปคุยกับ AI หรือกรรมการได้ตรงกัน

### แต่ละหน้า

| หน้า | ทำอะไร |
|---|---|
| 1 เชื่อมต่อ | เลือกบอร์ดจริง / ตัวจำลอง → เชื่อมต่อ หน้านี้แสดง:<br>• ผลการเชื่อมต่อ (พอร์ต, HELLO, ค่าตั้ง, telemetry)<br>• คำสั่งด่วน<br>• สุขภาพระบบ (อุณหภูมิชิป, หน่วยความจำ, แบต)<br>• ติ๊ก "ต่อใหม่เอง" เมื่อบอร์ดรีเซ็ต<br>• ตอนใช้ตัวจำลองมีแผงปรับโลกจำลอง |
| 2 ฮาร์ดแวร์ | • HWID (ชิป, PSRAM, flash, สาเหตุรีเซ็ต) และ DIAG<br>• PINFIND: เอามือบัง LDR แล้วดูว่าแท่งไหนขยับ → ตั้งเป็นขาซ้าย/ขวา |
| 3 คาลิเบรต | 8 ขั้น มีปุ่ม "ถัดไป" ทุกขั้น:<br>01 ตั้งค่า (ZERO, วัด backlash → "ใช้ค่านี้", SPR; รุ่น LDR, α, วงจร)<br>02 แสงรอบข้าง (ปิดหลอด; **ห้ามข้ามถ้าห้องเปิดไฟ**)<br>03 Balance (ข้ามได้)<br>04 Sweep (กวาด −60..60 อัตโนมัติ)<br>05 Fit: Sweep เสร็จแล้วทำให้เอง มีกล่องตัดสิน ผ่าน/เตือน/ไม่ผ่าน และขั้นย่อย "γ สองระดับแสง" (เอากระดาษบังหลอด)<br>06 ตรวจความแม่น (กวาดย้อนทิศ)<br>07 ส่งเข้าบอร์ด + SAVE<br>08 ตั้งศูนย์กับของอ้างอิงจริง (**ห้ามข้าม**) |
| 4 ภารกิจ 1 | ตั้งมุมแสงเป้า, เกณฑ์ ±, เวลาคงเป้า แล้วกด "เริ่ม" หน้านี้มี:<br>• หน้าปัดมุม<br>• แถบนับเวลาคงเป้า<br>• กล่องผลรอบล่าสุด<br>• กราฟ error<br>• ตารางทุกรอบ ("ผ่าน" เมื่อทุก sample ในช่วงคงเป้าอยู่ในเกณฑ์)<br>• ทดสอบ STEP |

| ค่าสด | • หน้าปัด<br>• กราฟ mV ของ LDR ซ้าย/ขวา (ฟ้า/ส้ม), กราฟ D, กราฟมุม<br>• ขยับตัวขับด้วยมือ (MOVE / GOTO / ZERO / RELEASE) |
| จูนค่า | ค่าตั้งทั้ง 78 ค่า "ค่าที่ใช้บ่อย" อยู่บนสุด<br>• แก้แล้วกด Enter = เข้าบอร์ดทันที (ยังไม่ถาวร)<br>• แถวที่มีแถบส้ม = ยังไม่ SAVE<br>• มีค้นหา และ Export / Import โปรไฟล์<br>• DEFAULTS ต้องพิมพ์คำว่า DEFAULTS ยืนยันก่อน |
| หลักฐาน & AI | • เขียน "อาการ" → "คัดลอกให้ AI": ได้ข้อความรวมสถานะบอร์ด, ค่าตั้ง, ผลคาลิเบรต, สถิติ, คำสั่งล่าสุด 20 บรรทัด และ error ล่าสุด เอาไปวางในแชท AI<br>• ดาวน์โหลด log / telemetry / หลักฐาน<br>• เล่นย้อนหลัง |

### ลูปแก้ปัญหากับ AI (ให้จบใน 10 นาที)

1. เจออาการ → ไปหน้า "หลักฐาน & AI" เขียนอาการสั้น ๆ
2. กด "คัดลอกให้ AI" แล้ววางในแชท
3. AI ตอบเป็นคำสั่ง เช่น `SET ctl.k 0.6` → พิมพ์ใน Console
4. ทดสอบ ถ้าดีขึ้นกด SAVE (ป้าย "ยังไม่ SAVE" บนแถบบน)

`firmware/CONTEXT_PACK.md` คือสรุปการทำงานของระบบแบบสั้น วางให้ AI ตัวใหม่อ่านก่อนได้

### ทางลัด (ไว้ซ้อมหรือถ่ายภาพหน้าจอ)

`NasaSatLab.html#sim` = ต่อตัวจำลองทันที ต่อท้ายได้อีก:
- `&tab=m1` (connect / hw / cal / m1 / m2 / live / tune / ev)
- `&step=5` (เปิดขั้นคาลิเบรต)
- `&theme=dark`
- `&cmd=M1 START` (หลายคำสั่งคั่นด้วย `;`, `wait 2000` = รอ 2 วินาที)

## ส่วนที่ 3 — Hand-off สำหรับ AI ที่จะทำต่อ

> เขียนโดย Claude (Opus) วันที่ 1 ต.ค. 2026 ตอนย้ายเครื่อง ความจำของ AI ตัวเก่าไม่ได้ตามมาด้วย ทุกอย่างที่ต้องรู้จึงอยู่ในส่วนนี้ อ่านให้จบก่อนเริ่ม แล้วอ่านไฟล์ที่เกี่ยวข้องให้ครบทุกไฟล์

### 3.1 วิธีทำงานกับทีมนี้ (สำคัญกว่าโค้ด)

- **ผู้ใช้และภาษา**:
  - ผู้ใช้เป็นนักเรียน ม.ปลาย ทีม "นาซ่าหน้าปากซอย" (1 ใน 10 ทีมรอบชิง ภาคตะวันออก)
  - พิมพ์ไทยแบบสบาย ๆ มีคำผิด: **ตอบเป็นภาษาไทย**
  - อธิบายให้ชัด แต่เนื้อหาต้องลึกระดับแชมป์
- **อ่านไฟล์ให้ครบทุกไฟล์** ก่อนวิเคราะห์หรือสร้างของ (ผู้ใช้ย้ำ "อ่านให้ครบทุกไฟล์")
- **ถามก่อนทำอะไรที่เป็นภัย** ผู้ใช้สั่งไว้ว่า "ถามผมก่อนด้วยนะจะทำอะไรที่เป็นภัย" ได้แก่:
  - ลบ / เขียนทับ
  - ติดตั้งโปรแกรม / ไดรเวอร์ / board core
  - อะไรก็ตามที่ย้อนกลับไม่ได้
- **ใช้ AI ได้ตามกติกา**: ห้ามแค่ความช่วยเหลือจากคนนอกทีม และกรรมการชมวิธีใช้ AI ตอนรอบภูมิภาค **ไม่ต้องเตือนเรื่องนี้อีก**
- **แหล่งข้อมูลที่เชื่อได้**:
  - `reference/research_ai_reports/` มาจาก AI ที่อ่อนกว่า (เนื้อหาวนซ้ำ ขาดหาย สูตรผิด pseudocode มีบั๊ก) ใช้ดูได้แค่ว่ามีหัวข้ออะไร **ห้ามลอกสูตรหรือโค้ด** ต้องคิดใหม่และทดสอบเอง
  - ข้อเท็จจริงเรื่องกติกาและกำหนดการ ยึด PDF ใน `reference/official/` เท่านั้น ถ้าขัดกันยึด "กำหนดการรอบชิงชนะเลิศอันล่าสุด(...).pdf"
  - ไฟล์ `BDE ...(2).md` คือข้อความที่แปลงจาก PDF ซึ่งเพี้ยนบางส่วน
- **งานใหญ่ทำเป็นชุด ให้ผู้ใช้อนุมัติทีละชุด**:

### 3.6 หลักการและเหตุผล (ทำไมออกแบบแบบนี้)

**แสง → มุม (estimator)**
- LDR สองตัวเอียง ±α จากแกนหน้า แต่ละตัวรับแสงตามกฎโคไซน์ L ∝ cos(θ−α), R ∝ cos(θ+α) จะได้
  - D = (L−R)/(L+R) = tan θ · tan α
  - θ = atan(D / tan α)
- ค่า ADC มาจากวงจรแบ่งแรงดัน ซึ่งไม่เป็นเชิงเส้นกับแสง จึงทำตามลำดับนี้ทีละช่อง:
  1. แปลงเป็น conductance G = V/(Vcc−V) (กลับด้านตาม `sen.topo`)
  2. ยกกำลัง 1/γ ของ LDR ตัวนั้น (G ∝ E^γ)
  3. หักแสงรอบข้างที่วัดตอนปิดหลอด
  4. ถอดราก q (รูปทรงกล่องครอบ)
  5. **แล้วจึงคูณ gain ของช่อง** (ถ้าคูณก่อนถอดราก จุดศูนย์เลื่อน ~6°)
- ความสว่างหลอด K จะตัดกันใน D ก็ต่อเมื่อเลขชี้กำลังรวมของสองช่องเท่ากัน
  - Sweep ที่ความสว่างเดียวแยก γ กับ q ไม่ออก
  - จึงวัด **อัตราส่วน γ จากแสงสองระดับ** (กระดาษขาวบังหน้าหลอดให้แสงลด ≥ 2 เท่า ห้ามขยับดาวเทียม) แล้ว Fit ด้วย q เดียวกันสองช่อง
  - ผลในโลกจำลอง (กล่องครอบไม่เท่ากัน, ห้องสว่าง, หลอด ×0.5/×1.8): คลาดลดจาก ±3.3–3.6° เหลือ 0.09°
  - ใช้ q ร่วมโดยไม่มีอัตราส่วนที่วัดได้ **แย่กว่าเดิม** (1.1° เทียบ 0.5°)
- Fit (Levenberg–Marquardt) บนจุด Sweep:
  - เลือกเฉพาะจุดที่เป็นแสงหลอดล้วน (หักแสงห้องก่อนเลือก) ถ้านับแสงห้องด้วย จุดหางที่กล่องบังจะเข้ามาทำให้คลาด 8–22°
  - ตัดจุดที่ ADC ตัน
  - ใช้ LUT แก้ส่วนที่เหลือ
- หลัง Fit ยังมีศูนย์เยื้องคงที่ 0.2–0.7° ซึ่งแก้ได้ด้วยของอ้างอิงภายนอกเท่านั้น จึงต้องทำ **CAL TH0** (บอร์ดบันทึกลง flash เอง)
- ลำดับคาลิเบรต:
  1. หันหาหลอด → `ZERO`
  2. `BACKLASH` → ตั้ง `act.bl` (→ `SPR` ถ้าหมุน 360° ได้)
  3. `AMB` ตอนปิดหลอด (บังคับถ้าห้องเปิดไฟ)
  4. `SWEEP`
  5. γ สองระดับ
  6. Fit
  7. ตรวจความแม่น (กวาดย้อนทิศ)
  8. ส่งเข้าบอร์ด + SAVE
  9. `CAL TH0` กับของอ้างอิง
  10. boresight กล้อง (ต้องทำหลังข้อ 9)
- **ไฟห้องเปลี่ยน**:
  - ตรวจศูนย์ด้วยท่อเล็ง → ทำ `CAL TH0` ใหม่อย่างเดียว
  - ห้ามวัด AMB ใหม่อย่างเดียว และห้าม Fit ใหม่ด้วย Sweep เก่า (แย่ลงถึง 3°)
- ทางเลือกที่พิจารณาแล้วไม่ใช้:
  - กวาดแล้ว cross-correlation
  - synchronous detection
  - Kalman filter
  - PID เต็มรูป
- แบบ "วัด → หมุน → รอ + null-seek" เหมาะที่สุดกับเซนเซอร์ช้าและตัวขับแบบสั่งตำแหน่ง จุดที่ให้ผลจริงคือศูนย์สัมบูรณ์และความทนต่อความสว่าง

**การควบคุม (ภารกิจ 1)**
- รอบการทำงาน: วัดเฉพาะตอนตัวขับหยุด และรอ `ctl.wait` เพราะ LDR ช้า → หมุนแก้ k·error (`ctl.k` 0.85 ซึ่ง < 1 กันแกว่ง)
- เข้าเป้าจากทิศเดียวกันเสมอ (`ctl.appr`) + stepper ชดเชย backlash (`act.bl`) โดยนับ step ชดเชยที่ทำไปแล้ว (`off_`)
- การล็อก (HOLD):
  - เข้า HOLD เมื่ออยู่ใน `ctl.db` ติดกัน `ctl.nlock` ครั้ง
  - หลุด HOLD เมื่อเกิน `ctl.hys`
  - ระหว่าง HOLD ถ้าเกิน db ติดกัน `ctl.trim` ครั้ง จะขยับแก้ด้วยค่าเฉลี่ยโดยไม่หลุด HOLD
- `ctl.adapt`: ประมาณ noise จากผลต่างของหน้าต่างติดกัน แล้วเฉลี่ยนานขึ้นได้ถึง 400 ms และขยาย db ≥ 2.5×noise ผลจำลองที่ noise 25 mV: ล็อกใน 3–10 s คลาด ≤ 0.27°
- SEARCH:
  - หมุนต่อเนื่อง หยุดที่ค่าแรกที่ใช้ได้**และหมุนไปถึงได้** (มุมแสงวนรอบได้ แต่ตัวขับหมุนรอบไม่ได้)
  - แก้แล้วเลยเป้าจะลด gain ลงครึ่ง
  - null-seek จบที่จุดตัดศูนย์ที่คำนวณจากค่าสองฝั่ง
- **ไม่รายงานผ่านปลอม**: ADC ตันถือว่าไม่ valid เว็บตัดสินว่า M1 ผ่านเมื่อครบทุกข้อ:
  - ทุก sample ในช่วงคงเป้าเป็น HOLD, เห็นแสง, ไม่ตัน และ |error| ≤ เกณฑ์
  - ข้อมูลไม่ขาดช่วงเกิน 0.5 s
  - ได้ sample อย่างน้อย 80% ของที่ควรได้
- **ตั้งใจไม่ทำ** M1 offset mode (Opus F08): หลังแก้ F04 มุมนอกศูนย์ก็ไม่เพี้ยนตามความสว่างแล้ว และโจทย์น่าจะใช้มุมเป้า 0

**ภารกิจ 2 / กล้อง**
- จุดบนภาพ → มุม: az = cam_az + s·atan((W/2 − x)/f) โดย f = (W/2)/tan(hfov/2) และ s = `cam.dir` × (`cam.hmirror` ? −1 : 1)
- `cam.dir` กับ `cam.hfov` วัดจาก SNAP → MOVE +8 → SNAP:
  - correlate gradient ของโปรไฟล์คอลัมน์ ลองทั้งสองทิศและ HFOV 20–140° (u' = tan(atan(u·t) + s·D)/t)
  - ถ้าถ่ายผนังเรียบจะไม่ยอมสรุป
- boresight `cam.off = θ − δ`: คำนวณเฉพาะภาพที่ถ่ายตอน HOLD |θ| ≤ 2° และต้องทำหลัง CAL TH0
- M2 GO เข้าเป้าจากทิศ `ctl.appr` เสมอ (เลยไป 2° ถ้าต้องหมุนกลับ) มุมจากภาพเดียวกันจึงชี้ตรงกัน 0.00°
- `M2 GO SUN offset` หันเทียบทิศดวงอาทิตย์ที่หาได้ตอนนั้น จึงทนการโดนชน
- บอร์ด**ไม่ถ่าย**ถ้าเป้าอยู่นอก `act.min..act.max` หรือคลาดเกิน `m2.tol` (ตอบ `J snap_fail` พร้อมเหตุผล)
- preset กล้องทุกตัวถูกตรวจกับกฎขาของชิปก่อนเริ่มกล้อง (`cfg::gpioWhy`) เลือก preset ผิดชิปจะได้ `ERR CAM ... not for this chip` แทนการขับขา flash จนบอร์ดพัง
- การส่งภาพ: แบ่งเป็นชิ้น base64 (`IMG B/C/E`) + CRC32 เว็บขอชิ้นที่หายซ้ำได้ไม่เกิน 3 รอบ
- ตัวจำลองติดกล้องกลับหัวไว้โดยตั้งใจ (ทิศดิบ −1) เพื่อให้ซ้อมพลิกภาพ
- ใช้สองบอร์ดได้ (บอร์ดหลัก + ESP32-CAM): เปิดเว็บสองแท็บ แท็บละพอร์ต (ดู `firmware/README.md`)

**ไม่ต่อคอม / สื่อสาร (OBC, EPS, COMM)**
- `m1.auto N`: บูตแล้ว N วินาทีเริ่ม M1 เอง (STOP ยกเลิกได้)
- `hw.btn` (0 = ปุ่ม BOOT): กด = เริ่ม/หยุด ปิดเองถ้ากล้องใช้ขาเดียวกัน
- `J hk` ส่งทุก `com.hk` วินาที: อุณหภูมิชิป, heap, loop นานสุด, แรงดันแบต (`hw.vbat` × `hw.vdiv`)
- ช่องสื่อสารที่สอง (UART1 / วิทยุ):
  - ทุกบรรทัดออกผ่าน `emit()` ไป USB + ring buffer ของ UART1 (`com.rx`, `com.tx`, `com.baud`; 64 KB ถ้ามี PSRAM / 8 KB ถ้าไม่มี)
  - บัฟเฟอร์เต็มจะทิ้งทั้งบรรทัด
  - telemetry วิทยุตาม `com.lhz`; ภาพรอที่ว่าง (`com.limg`)
  - ที่ 9600 baud: ภาพ 320×240 ~9.6 s, 640×480 ~32 s
- **Wi-Fi / ESP-NOW ยังไม่ทำ** ถ้าต้องทำ ให้เพิ่มเป็นช่องปลายทางใหม่ข้าง UART ใน `proto.cpp` (โครงรองรับแล้ว) แล้วเทสต์ใน host test ก่อน
- เว็บต่อใหม่เองเมื่อพอร์ตหาย (หา VID:PID เดิม 30 s) และอ่านค่าบอร์ดใหม่หลัง `E BOOT`

### 3.7 กับดักที่เจอแล้ว (อย่าซ้ำ)

- **ชื่อชน POSIX ใน core จริง**: `stat`, `link` compile บน PC ผ่าน แต่ core จริงพัง
  - mock `Arduino.h` include `sys/stat.h` + `unistd.h` และประกาศ `link()` ไว้แล้ว
  - ตั้งชื่อตัวแปร global ให้เลี่ยงชื่อ libc
- Arduino สร้าง prototype ของ .ino อัตโนมัติ: struct ต้องอยู่ก่อนฟังก์ชันแรก (Fallback)
- protothread: ตัวแปร local คร่อม `WAIT_MOTION()` / `PT_SLEEP` จะ compile ไม่ผ่าน (jump to case label)
- e2e เคยผ่าน 106/106 เพราะดวงของ seed: ลอง `E2E_SEED=1..3` ทุกครั้ง
- SPR ต้องทำหลัง BACKLASH + ตั้ง `act.bl` (ถ้า act.bl = 0 จะได้ `E WARN SPR`)
- null-seek แบบบังคับเข้าจากฝั่งเดียววนไม่จบ ใช้จุดตัดศูนย์ + ลด gain ครึ่งแทน
- q ร่วมโดยไม่วัดอัตราส่วน γ แย่ลง และทฤษฎีที่ AI คิดเองเคยผิด `check_formulas.py` จับได้: เพิ่มสูตรใหม่ต้องเพิ่มข้อตรวจด้วย
- stepper: ปิด/เปิดการชดเชย backlash แล้วมุมเลื่อนไป `act.bl` แก้แล้วด้วย `off_` เทสต์ควรลองลำดับการใช้งานที่ "ไม่ปกติ" ด้วย
- boresight ก่อน CAL TH0 ผิดทั้งก้อน
- เทสต์ปุ่ม: ต้องปล่อย ≥ 100 ms ก่อนกดใหม่
- CSS: `[hidden]` ถูก `display:flex` ทับ จึงมีกฎ global `[hidden]{display:none!important}`
- เครื่องมือบน Windows:
  - g++ ใน Git Bash พังเงียบ ใช้ PowerShell
  - Bash กินเครื่องหมาย `\` ใน `node -e` (regex `\d`) และใน path แบบ `"$VAR\\$x"`

  - matplotlib ทำวรรณยุกต์ไทยหาย ใช้ `svg.fonttype='none'`

   - ซ้อมทั้ง 2 ภารกิจ ≥ 3 รอบ จับเวลา
   - ซ้อมกู้คืน (REBOOT, Import โปรไฟล์, Fallback)
   - หยุดแก้โค้ด 22:00

**จ. 9 ต.ค.** ทำตาม PLAYBOOK ข้อ 6:
- เช็ก RAW ว่าไม่ตัน
- ตรวจศูนย์ด้วยเลเซอร์ก่อนทุกรอบ (เพี้ยน > 0.3° → CAL TH0)
- จดผลและดาวน์โหลดหลักฐานทุกรอบ

### 3.9 สิ่งที่ยังค้าง / ยังไม่ได้ทำ / ข้อจำกัดที่รู้ (ทั้งหมด)

**ต้องใช้ของจริงถึงจะรู้**
- ไม่เคยรันบนบอร์ดจริง ที่ผ่านแล้วมีแค่ host test + compile จริง
- Web Serial กับบอร์ดจริงและการต่อใหม่อัตโนมัติ: ทดสอบได้แค่ตรรกะจับคู่พอร์ต
- เลือกโฟลเดอร์บันทึกภาพ: ต้องกดเอง ทดสอบอัตโนมัติไม่ได้
- `temperatureRead()` ระหว่างอ่าน LDR อาจเพิ่ม noise (TEST_PLAN B4)
- HWCDC ตอนไม่ต่อ USB (TEST_PLAN B14b)
- วิทยุจริง (HC-12/LoRa)
- กล้อง OV2640 จริง (ทิศภาพ, เลนส์บิดที่ขอบภาพ)
- ESP32-CAM จริง
- เครื่องหมายของ boresight ยืนยันได้แค่ในตัวจำลอง (Sonnet F12)
- **ตัวเลขความแม่นทั้งหมดเป็นผลจำลอง** (Opus F18, Sonnet F05): โลกจำลองทำ CAL TH0 ด้วยค่าความจริง ของจริงถูกจำกัดด้วยของอ้างอิง ต้องเอาข้อมูล TEST_PLAN B7/B8 มาแทนก่อนพูดกับกรรมการ
- ค่าเริ่มของการควบคุมยังไม่ได้จูนกับของจริง: ในจำลองปรับแล้วเร็วขึ้น ~1.5–2× (Sonnet F09); `ctl.nlock 2` ถ้ากรรมการจับเวลาเข้มข้น (Sonnet F17)
- `act.hold 0` (ค่าเริ่ม) ปล่อยขดลวด แท่นที่ถ่วงไม่สมดุลอาจไหล ให้ตั้ง `act.hold 1` (Sonnet F16)
- หลอดกรรมการแรงจน ADC ตัน (Opus F10, Sonnet F18): ระบบปฏิเสธถูกต้องแล้ว ทางแก้หน้างานคือ:
  - ถอยหลอดออก
  - ใช้กระดาษบางบังทั้งสองตัวให้เท่ากัน
  - เปลี่ยนตัวต้านทาน
  - แล้วคาลิเบรตใหม่

**ยังไม่ได้ทำ (อาจต้องทำ)**
- Wi-Fi / ESP-NOW / สถานีภาคพื้น: รอข้อมูล 6 ต.ค.
- preset กล้องบอร์ดอื่น เช่น DFRobot, LilyGO T-Camera S3, Waveshare (Sonnet F11) ตอนนี้มี `cam.model` 1/2/3 สำหรับ S3, 4 สำหรับ ESP32-CAM, 3 = กำหนดขาเองใน `board_config.h`
- โหมดระบบ SAFE ฯลฯ (Sonnet F13) ตอนนี้มีแค่ `J hk`
- parallax (Opus F15): ถ้าเซนเซอร์ไม่อยู่บนแกนหมุนหรือแกนหน้า error จะขึ้นกับระยะหลอด (2 cm ที่ 50 cm ≈ 2.3°)
  - วิธีรับมือ: ทำ CAL TH0 ที่ระยะหลอดจริงทุกครั้ง และติดเซนเซอร์ใกล้แกน
  - เอกสาร THEORY ยังไม่ได้เขียนเรื่องนี้
- ข้อเสนอจาก audit ที่ยังไม่ทำ (Sonnet 7.3, 8):
  - sketch ขั้นต่ำ ~60 บรรทัด (อ่าน 2 ขา → หมุนจน D = 0) เผื่อต้องผสมกับโค้ดผู้จัด
  - แผ่นสรุป 1 หน้า "ย้ายความรู้ไปใส่โค้ดผู้จัด"
  - ตาราง "กล้องเป็น X → ทำ Y"
  - หน้า "สิ่งที่เรารู้ว่ายังไม่รู้" ใน THEORY
- ตัวจำลอง JS ส่งค่าที่ผ่าน EMA ให้ procedure ขณะที่ firmware ใช้ค่าดิบ (Opus F20, P3) มีผลเฉพาะเมื่อ `sen.ema < 1` ในตัวจำลอง
- UI ส่วนที่อยู่ในแผนเต็มแต่ตัดออก (`UI_REDESIGN_PLAN_TH.md`): โหมดแข่ง/ผู้เชี่ยวชาญ, wizard 10 ขั้น, ปรับ checklist ฮาร์ดแวร์, แผงตัวจำลองแบบลอย (หลัง UI freeze ทำเฉพาะถ้าผู้ใช้ขอ)

**ตั้งใจไม่ทำ**
- M1 offset mode (Opus F08): เหตุผลอยู่ในข้อ 3.6

### 3.10 คำสั่งที่ใช้บ่อย

```
# เว็บ tool
node tool/build.js                       # src → NasaSatLab.html (ต้องรันทุกครั้งที่แก้ src)
node tool/tests/run_tests.js             # 97 ข้อ

# firmware บนคอม (ต้องมี g++ บน PATH; Windows: MSYS2 mingw64, รันจาก PowerShell)
cd firmware/host_test
node build.js                            # + --core2 / --esp32 / --fallback
node e2e.js                              # ตั้ง E2E_SEED=1 / 2 / 3 แล้วรันซ้ำ; e2e.js --core2 หลัง build --core2
node camnode_test.js                     # หลัง build --esp32
node fallback_test.js                    # หลัง build --fallback

# compile จริง (ใช้ arduino-cli ที่มากับ Arduino IDE 2.x หรือกำหนด ARDUINO_CLI=<path>)
node firmware/tools/compile_check.js --all

# ค่าตั้ง (หลังแก้ tool/src/js/06_cfgdefs.js)
node firmware/tools/gen_cfg.js

# เอกสาร
python docs/check_formulas.py
node docs/build_docs.js                  # .md → .html แล้วพิมพ์เป็น PDF ด้วย Chrome (A4, ไม่มี header/footer)
```

### 3.11 ถ้าจะแก้ X ต้องแตะอะไรบ้าง

- **เพิ่ม/แก้ค่าตั้ง**:
  1. `tool/src/js/06_cfgdefs.js`
  2. `node firmware/tools/gen_cfg.js`
  3. ใช้ค่าใน firmware (`cfg::i/f(CFG_...)`)
  4. ตัวจำลอง `07_sim.js`
  5. เทสต์ทั้งสองฝั่ง
  6. build เว็บใหม่
- **เปลี่ยนพฤติกรรม firmware**:
  1. แก้โค้ด (`procs.cpp` ฯลฯ)
  2. แก้ `07_sim.js` ให้ตรงกัน
  3. เพิ่มเทสต์ใน `e2e.js`
  4. รัน e2e หลาย seed + `--core2`
  5. รัน compile_check
  6. อัปเดต `PROTOCOL.md` / `README.md` / `CONTEXT_PACK.md`
  7. ถ้ามีสูตรใหม่ เพิ่มใน `check_formulas.py` + THEORY
- **แก้ UI**:
  1. แก้ `tool/src`
  2. build → run_tests
  3. ภาพหน้าจอ 1366×768 ทั้งสองธีม + ลองกดกับตัวจำลอง (Space/Esc, รายการปัญหา, SAVE, คาลิเบรต, M1, M2)
  4. id ทั้งหมดต้องยังอยู่
  5. หลัง 4 ต.ค. แก้เฉพาะบั๊ก
- **แก้เอกสาร**:
  1. แก้ไฟล์ `.md`
  2. `build_docs.js`
  3. พิมพ์ PDF ใหม่
  4. ถ้าแตะสูตรหรือตัวเลข ให้รัน `check_formulas.py`
- **ทุกชุดงาน**: สำรอง → แก้ → เทสต์ทั้งหมด → บันทึกใน `review/` → อัปเดตส่วนที่ 3 ของ README นี้
