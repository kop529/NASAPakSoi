# แผนทดสอบ NasaSat

หลักการ: **เก็บผลทุกครั้งรวมครั้งที่ล้มเหลว** ตัดสินด้วยการวัดจากของอ้างอิงภายนอก (โปรแทรกเตอร์, ท่อเล็ง, ภาพกล้อง) ไม่ใช่ตัวเลขที่บอร์ดรายงานเอง
ใช้ tool แท็บ "หลักฐาน & AI" → ดาวน์โหลด log / telemetry / evidence หลังทุกชุดทดสอบ

สิ่งที่ `e2e.js` ตรวจเพิ่มในชุด 2: ชุดขากล้อง ESP32-CAM บน S3 ถูกปฏิเสธ (บอร์ดไม่พัง), กล้องตั้ง hmirror/vflip เองและบอกใน img_meta, M2 GO เข้าเป้าทิศเดียวกันเสมอ (backlash ไม่ชดเชยก็ชี้ตรงกัน), เปิดชดเชย backlash กลับแล้วมุมตัวขับไม่เลื่อน, `J hk` + แรงดันแบต, ปุ่ม BOOT (กดค้างทำครั้งเดียว), `m1.auto` หลังรีบูต + STOP ยกเลิก, `SAVE k`, ช่องที่สองผ่านวิทยุ 9600 baud (telemetry 2 Hz, คำสั่งจากวิทยุ, ข้อมูลล้นทิ้งทั้งบรรทัด, loop ไม่รอ, ภาพ 320×240 และ 640×480 ผ่านวิทยุครบ)
สิ่งที่ `e2e.js` ตรวจ (ย่อ): protocol ทุกคำสั่งและ error, ค่าตั้งตรงกับเว็บ 78 ค่า, γ สองระดับแสง, กล่องครอบสองข้างไม่เท่ากัน, หาแสงตอนหลอดอยู่ข้างหลัง, ADC noise 25 mV, M1 ก่อนคาลิเบรต, ขาอันตรายถูกปฏิเสธ (ERR PIN), แก้ error ค้างขณะ HOLD (M1TRIM), CAL TH0 บันทึกเองและอยู่รอดหลังรีบูต, กล้องไม่ส่งภาพไม่ทำให้ watchdog รีเซ็ต, หาขา/ขาผิด/ทิศกลับ, SPR, BACKLASH, AMB รอ LDR นิ่ง, Sweep → Fit (ของเว็บ) → ส่งค่า → มุมตรงกับเว็บ, ศูนย์จากของอ้างอิง (CAL TH0), ไฟกระพริบ 30%, M1 ล็อก/ชน/หลอดย้าย/ดับ/หรี่/สว่าง, ADC ตันต้องไม่ HOLD, BUSY/STOP, ภารกิจ 2 ทุกโหมด, ไม่ถ่ายเมื่อเป้าเกินขอบเขต/ไม่ถึง tol, SNAP ระหว่าง M1, GO แย่งจาก M1, ภาพขาดแล้วขอซ้ำ, ภาพเสียถาวรไม่ทำให้ค้าง, STOP ตอบเร็วขณะส่งภาพผ่าน UART, servo 14 บิต, SAVE/REBOOT/LOAD, ห้องสว่าง 30%

ตัวเลขจากโลกจำลอง (ไม่ใช่ของจริง):

| รายการ | ผล |
|---|---|
| มุมคลาดหลัง Sweep+Fit อย่างเดียว | ค่าคงที่ −0.14 ถึง −0.37° (กระจาย 0.06°) แล้วแต่ seed |
| หลัง CAL TH0 | MAE 0.05–0.09°, สูงสุด 0.10–0.26° |
| M1 จากห่าง 75° | เข้าเป้า 4.4–4.6 s คลาดจริง < 0.1° |
| M1 ก่อนคาลิเบรตเซนเซอร์ (ค่าที่อ่าน ~1.6 เท่าของจริง) | ล็อกได้ใน 4 s (ลด gain เองเมื่อแก้เลยเป้า) |
| หลอดอยู่หลังดาวเทียม (+140° / −140°) | SEARCH แบบหมุนต่อเนื่อง → HOLD 6.1 s / 14.4–15 s (วิธีเดิม 20–29 s) |
| ADC noise 25 mV ต่อ sample (`ctl.adapt 1`) | ล็อก 2.9–9.7 s คลาดจริง ≤ 0.27° ทั้ง `ctl.db` 0.3 และ 0.15 (วิธีเดิม 6–22 s หรือไม่ล็อก) |
| หลอดหรี่ 55% / สว่าง 1.9× (มี γ สองระดับ) | เซนเซอร์เพี้ยน −0.03 ถึง 0.09° (ก่อนมี γ สองระดับ: 0.5°) ตำแหน่งจริง ≤ 0.09° |
| ห้องสว่าง 30% + กล่องครอบไม่เท่ากัน (q 1.25/1.45) หลอด 0.5–1.8× | คลาด 0.09° (ไม่วัด γ สองระดับ: +3.62 / −3.27°) |
| ไฟห้องเปลี่ยนหลังคาลิเบรต (3% ↔ 30%) ไม่ทำอะไร / วัด AMB ใหม่อย่างเดียว | มี γ สองระดับ: ≤ 0.33° / ≤ 0.30°; วิธีเดิม: ≤ 1.9° / แย่ลงถึง 3.1° |
| ภารกิจ 2 เทียบทิศดวงอาทิตย์หลังโดนชน 7° | คลาด −0.18 ถึง +0.09° ใน 4 seed (เทียบศูนย์ตัวขับ: ~6.2°) |
| M2 GO มุมเดียวกัน มาจากบนและล่าง (ไม่ชดเชย backlash 1.4°) | ต่างกัน 0.00° (ก่อนแก้ 1.3°) |
| ส่งภาพ 640×480 ผ่าน UART 115200 | 3.0 s, STOP ตอบภายใน 20 ms |
| ภาพผ่านวิทยุ 9600 baud ช่องที่สอง | 320×240: 9.6 s, 640×480 (ไม่มี PSRAM, บัฟเฟอร์ 8 KB): 32.4 s ครบทั้งสองฝั่ง loop นานสุด 199 ms (เวลาเฟรมกล้องเอง) |
| ตรวจทิศภาพในเว็บ (ตัวจำลอง, กล้องติดกลับหัว 180°) | ทิศถูก, มุมรับภาพ 63.9° (จริง 64°) |

โลกจำลองมีอะไร: LDR 2 ตัว γ ต่างกัน (0.62/0.57) ความต้านทานต่างกัน ติดเอียงไม่เท่ากัน (31.0°/30.6°) กล่องครอบบังขอบ หน่วงขึ้น 25 ms ลง 35 ms ไฟกระพริบ 100 Hz noise ADC ตันที่ 3100 mV มอเตอร์หมุนตามลำดับขดลวดที่ firmware ส่งจริง step ต่อรอบ 4076 backlash 1.4° กล้องเยื้อง 2.2° I2C/NVS/LEDC บังคับข้อจำกัดเหมือนชิป ปุ่ม BOOT (pull-up) วงจรแบ่งแรงดันแบต วิทยุ serial ที่ส่งตามเวลาจริงของ baud และต้องต่อขา/baud ตรงจึงได้ยิน
ตัวจำลองในเว็บ: กล้องติดกลับหัว 180° (ฝึกพลิกภาพ + ตรวจทิศภาพ) ห้องมีของติดผนังไม่สม่ำเสมอให้เทียบภาพได้
**ไม่มีในโลกจำลอง**: แสงสะท้อน, หลอดไม่ใช่จุด, สายไฟดึง, แรงเสียดทาน, ADC ไม่เชิงเส้น, USB/ไฟตกของจริง, คุณภาพภาพจริง, เลนส์บิดเบี้ยว, Web Serial (การต่อใหม่อัตโนมัติยังไม่ได้ลองกับพอร์ตจริง)

## C. วันแข่ง

**8 ต.ค. 13:00–17:00 (ปรับจูน + ซ้อม)**
1. B2 → B3 กับชุดจริงของผู้จัด จด pinout, ชนิดตัวขับ, กล้อง, ไฟเลี้ยง, core ที่ผู้จัดกำหนด
2. รันตัวอย่างโค้ดของผู้จัดให้ผ่านก่อน 1 ครั้ง (รู้ว่าฮาร์ดแวร์ปกติ)
3. คาลิเบรตครบทุกขั้น (รวม γ สองระดับแสง: พกกระดาษขาว/กระดาษไข) ใต้แสงจริงของห้องแข่ง → Export ผลคาลิเบรต + Export โปรไฟล์ เก็บไว้ 2 ที่
4. ซ้อมภารกิจ 1 และ 2 ต่อเนื่องตั้งแต่เปิดเครื่อง อย่างน้อย 3 รอบ จับเวลาทุกขั้น
5. ซ้อมกู้คืน: REBOOT, เสียบสายใหม่, Import โปรไฟล์
6. ถ้าผู้จัดให้ถอดสาย/ใช้สถานีภาคพื้น: ซ้อม B14b (m1.auto + ปุ่ม) และ B14c (ช่องที่สอง) ด้วยของจริง
7. เลือกโฟลเดอร์บันทึกภาพอัตโนมัติในแท็บภารกิจ 2 แล้วดาวน์โหลด evidence ทั้งหมด

**9 ต.ค. 08:30 (ฟังโจทย์) – 12:00**
1. แปลงโจทย์เป็นรายการผ่าน/ไม่ผ่าน: มุมเป้า, tolerance, เวลาจำกัด, วิธีวัดของกรรมการ, ต้องส่งภาพแบบไหน
2. ตั้ง `m1.tgt`, `m1.tol`, `m2.tol`, `act.min/max`, `m2.tgt` หรือ offset ตามโจทย์
3. ถ้าแสงห้องต่างจากเมื่อวาน: ตรวจศูนย์ด้วยท่อเล็ง ถ้าคลาดเกินเกณฑ์ CAL TH0 ใหม่ (อย่าวัด AMB ใหม่อย่างเดียว)
4. ก่อนเริ่มจริง: RAW 1 ครั้ง (ไม่ตัน, valid), M1 ทดลอง 1 รอบ
5. ระหว่างแข่ง: คนคุมคีย์บอร์ด 1 คน (STOP = Space/Esc), คนดูค่า/จดเวลา 1 คน, คนดูฮาร์ดแวร์ 1 คน

## D. แบ่งงานสมาชิก 3 คน
- **เซนเซอร์/ควบคุม**: คาลิเบรต, M1, อธิบายสูตร θ = atan(D/tan α) และทำไมต้องวัด AMB + ตั้งศูนย์กับของอ้างอิง
- **กล้อง/สื่อสาร**: M2, boresight, การส่งภาพ, protocol
- **คุมเครื่อง/บันทึก**: checklist, จดผลทุกรอบ, export หลักฐาน, แผนสำรอง
