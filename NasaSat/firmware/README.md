# NasaSat firmware (ESP32-S3) — ทีมนาซ่าหน้าปากซอย

firmware ตัวแข่งของเรา ใช้คู่กับเว็บ tool `tool/NasaSatLab.html` ทำได้ทั้ง 2 ภารกิจ
- **ภารกิจ 1 Sun Tracking**: LDR 2 ตัววางเป็นตัว V คำนวณมุมแสง แล้วหมุน stepper 28BYJ-48 (ULN2003) หรือ servo ให้หันเข้าหาแสง
- **ภารกิจ 2 Target Imaging**: หันกล้องไปมุมเป้าหมาย (เทียบศูนย์ตัวขับ หรือเทียบทิศดวงอาทิตย์) แล้วถ่าย JPEG ส่งกลับทาง USB
  ไม่รู้มุมเป้า: เว็บสแกนถ่ายรอบตัว แล้วคลิกที่เป้าในภาพ → บอร์ดหันไปถ่ายให้
- **ไม่ต่อคอมก็ทำงานได้**: เริ่มภารกิจ 1 เองหลังเปิดเครื่อง (`m1.auto`), ปุ่ม BOOT เริ่ม/หยุด (`hw.btn`), สุขภาพระบบ `J hk` (อุณหภูมิชิป,
  หน่วยความจำ, แรงดันแบต), ช่องสื่อสารที่สองผ่านวิทยุ serial (`com.tx/com.rx`)

ทุกค่า (ขา, ตัวขับ, ค่าคาลิเบรต, ค่าควบคุม) ตั้งผ่านคำสั่ง `SET` แล้ว `SAVE` เก็บใน flash **ไม่ต้องแก้โค้ดหรืออัปโหลดใหม่ที่หน้างาน**

## เริ่มใช้ (ครั้งแรก)

1. เตรียมเครื่องตาม `INSTALL_CHECKLIST.md` แล้วกด Verify (✓) ให้ผ่านก่อน **ทำได้แม้ยังไม่มีบอร์ด**
2. เสียบบอร์ด เลือกพอร์ต กด Upload
3. เปิด `tool/NasaSatLab.html` ด้วย Chrome หรือ Edge → แท็บเชื่อมต่อ → บอร์ดจริง → เชื่อมต่อ
   (ปิด Serial Monitor ของ Arduino ก่อน พอร์ตใช้ได้ทีละโปรแกรม)
4. ต้องเห็น `hello` และ telemetry วิ่ง ถ้าไม่เห็นดูหัวข้อ "แก้ปัญหา"

## ตั้งค่ากับชุดของผู้จัด (ทำครั้งเดียวต่อชุด ประมาณ 5 นาที)

1. **HWID** (แท็บฮาร์ดแวร์): ดูชิป, PSRAM, flash, สาเหตุรีเซ็ต
2. **หาขา LDR**: `PINFIND ON` แล้วเอามือบัง LDR ทีละตัว ขาที่ค่าเปลี่ยนมากคือขานั้น → ตั้ง `sen.pin0` (ซ้าย) และ `sen.pin1` (ขวา)
3. **วงจร LDR**: บังมือแล้ว mV ลด = `sen.topo 0` ถ้า mV เพิ่ม = `sen.topo 1`
4. **ขา ULN2003**: ดูจากลายวงจร/สกรีนบนบอร์ด หรือโค้ดตัวอย่างของผู้จัด → `act.in1..act.in4`
   ตรวจว่าหมุนจริง: `MOVE 10` ต้องหมุน ถ้าไม่หมุนแปลว่าขายังไม่ตรง
5. **ทิศมอเตอร์**: หันเข้าหลอดคร่าว ๆ ดู θ แล้วสั่ง `MOVE 10` θ ต้อง**ลดลง** ถ้าเพิ่มขึ้นให้ `SET act.dir -1`
6. **กล้อง** (ถ้ามี): `SET cam.model 1` (ESP32-S3-EYE/Freenove) หรือ `2` (XIAO) หรือ `4` (ESP32-CAM AI-Thinker) หรือ `3` (แก้ขาใน `board_config.h`) แล้ว `M2 INIT`
   ชุดขาของชิปอื่นจะถูกปฏิเสธพร้อมเหตุผล (`not for this chip`) ไม่ทำให้บอร์ดพัง แล้วทำ "เตรียมกล้อง" ในแท็บภารกิจ 2 (พลิกภาพ → ตรวจทิศภาพ)
7. `SAVE`

## คาลิเบรต (ลำดับนี้สำคัญ)

| ขั้น | ทำอะไร | ทำไม |
|---|---|---|
| 1 | หันเข้าหาหลอดคร่าว ๆ แล้ว `ZERO` | ให้ Sweep ครอบหลอดตรงกลาง |
| 2 | `BACKLASH` → ตั้ง `act.bl` ตามผล | เฟืองมีระยะฟรี ~1–2° **ต้องทำก่อน SPR** |
| 3 | (ถ้าหมุนได้ 360°) `SET act.max 720` → `SPR` → ตั้ง `act.spr` ตามผล → `MOVE -360` → `SET act.max 170` | 28BYJ-48 จริงมี 4076–4096 step/รอบ ไม่เท่ากันทุกตัว ถ้ายังไม่ตั้ง `act.bl` ค่าจะคลาดได้ถึง ~17 step (บอร์ดเตือน `E WARN SPR`) |
| 4 | **ปิดหลอด** → แท็บคาลิเบรตขั้น 2 (AMB) | **ห้ามข้ามถ้าห้องเปิดไฟ** บอร์ดรอให้ LDR นิ่งเองก่อนวัด |
| 5 | เปิดหลอด → ขั้น 4 Sweep −60..60 ทีละ 5 | เก็บรูปการตอบสนองของ LDR |
| 5.5 | ขั้น 5 "γ สองระดับแสง": หันเข้าหลอด → วัดระดับ 1 → กระดาษขาวบังหน้าหลอด (แสงลด ≥ 2 เท่า, ห้ามขยับดาวเทียม) → วัดระดับ 2 | Sweep ความสว่างเดียวแยก γ กับ q ไม่ออก ถ้าไม่วัด มุมเพี้ยนเมื่อหลอดสว่างเปลี่ยน (ตัวจำลอง: 0.5° เมื่อหลอดหรี่ครึ่งหนึ่ง, 3–4° ถ้ากล่องครอบสองข้างไม่เท่ากัน) |
| 6 | ขั้น 5 Fit → ขั้น 6 ตรวจ (กวาดย้อนทิศ) → ขั้น 7 ส่ง + SAVE | ได้ γ ของ LDR แต่ละตัว (อัตราส่วนจากขั้น 5.5), q เดียวกันสองช่อง, g, ตาราง LUT |
| 7 | ขั้น 8: หันหน้าดาวเทียมตรงหลอดด้วย**ของอ้างอิงภายนอก** แล้ว `CAL TH0 0` (บอร์ดบันทึกค่าศูนย์ลง flash ให้เอง ตอบ `"saved":true`) | Sweep + Fit หาศูนย์สัมบูรณ์เองไม่ได้ |
| 8 | กล้อง: แท็บภารกิจ 2 "เตรียมกล้อง": พลิกภาพให้ตั้งตรง → "ตรวจทิศภาพ" (ถ่าย → หมุน +8° → ถ่าย ได้ `cam.dir` + `cam.hfov`) → "ล็อกหลอดแล้ววัด boresight" → ใช้ค่านี้ + SAVE | กล้องติดเยื้องจากแกนเซนเซอร์ และภาพอาจกลับด้าน: ใช้ทิศผิด มุมคลาดเป็นสองเท่า |

ผลในตัวจำลอง (firmware C++ ตัวจริง, `host_test/e2e.js`): หลังขั้น 1–6 มุมคลาดเป็นค่าคงที่ ~0.37° (ขั้น 6 มองไม่เห็นเพราะใช้ผล Fit เป็นเฉลย) หลัง `CAL TH0` เหลือ MAE 0.04° สูงสุด 0.10°
ห้องเปิดไฟสว่าง 30% ของหลอด ถ้าข้าม AMB คลาดราว 5–15° ถ้าทำ AMB + γ สองระดับ คลาด 0.09° แม้หลอดสว่างเปลี่ยน 0.5–1.8 เท่าและกล่องครอบสองข้างไม่เท่ากัน (ไม่วัด γ สองระดับ: 3.3–3.6°)
ไฟห้องเปลี่ยนทีหลัง: ตรวจศูนย์ด้วยท่อเล็ง ถ้าคลาดให้ `CAL TH0` ใหม่ **อย่าวัด AMB ใหม่อย่างเดียว** (ทดลองแล้วแย่ลงได้ถึง 3° ถ้าไม่ได้วัด γ สองระดับ)
**ตัวเลขทั้งหมดนี้มาจากโลกจำลอง ของจริงต้องวัดซ้ำกับบอร์ดและของอ้างอิงภายนอก (ดู `TEST_PLAN.md`)**

## ภารกิจ 1 (Sun Tracking)

- `M1 START [มุม]` (ค่าเริ่ม 0 = หันตรงเข้าหาแสง) หยุดด้วย `M1 STOP` หรือ `STOP`
- สถานะ (event `E M1 ...`): `FINE` กำลังปรับ → `HOLD` ล็อกแล้ว (มี `t=` เวลา, `it=` จำนวนรอบ, `err=`, `sd=` noise ของค่าที่วัด) → ถ้ามีคนชน/หลอดย้าย จะกลับไป `FINE reacquire` เอง
- ล็อกแล้วคลาดค้างเกิน `ctl.db` ติดกัน `ctl.trim` ครั้ง (หลอดขยับนิดหน่อย, สายดึง): ขยับแก้โดยยัง HOLD (`E M1TRIM`)
- หาไม่เจอ (หลอดอยู่หลังดาวเทียม): `SEARCH` หมุนต่อเนื่องแล้วหยุดทันทีที่เห็นแสงในมุมที่หมุนไปถึงได้ หมุนไปทางที่เห็นแสงครั้งล่าสุดก่อน (ตัวจำลอง: 6–15 วินาที วิธีเดิม 20–29 วินาที) → `LOST no_light` ถ้าไม่เจอเลย
- noise สูง: `ctl.adapt 1` (ค่าเริ่ม) ให้บอร์ดเฉลี่ยนานขึ้นเอง (สูงสุด 400 ms) และขยาย deadband เท่าที่จำเป็น (ตัวจำลอง noise 25 mV: ล็อกใน 4 วินาที วิธีเดิม 6–22 วินาทีหรือไม่ล็อกเลย) ดู noise ได้จาก `RAW 1000` ฟิลด์ `th_sd`
- ถ้าค่าที่อ่านได้ยังไม่ถูกสเกล (ก่อนคาลิเบรต) จนแก้ทีไรเลยเป้า บอร์ดลด gain ลงครึ่งเองจนนิ่ง
- **ADC ตัน** (แสงแรงจน mV ชนเพดาน ~3050): บอร์ด**ไม่ล็อก**จากค่าที่ตัน ขึ้น `adc_saturated` ให้ถอยหลอด, ปิดคู่ LDR ด้วยกระดาษบางให้เท่ากัน หรือเปลี่ยนตัวต้านทาน แล้วคาลิเบรตใหม่
- ทดสอบความเร็วตอบสนอง: ขณะ HOLD สั่ง `STEP 10` จะได้ `step_result` (เวลากลับเข้าเป้า, error สูงสุด)
- เว็บตัดสิน "ผ่าน" ก็ต่อเมื่อ**ทุก sample** ในช่วงคงเป้าต่อเนื่อง (ค่าเริ่ม 3 วินาที) เป็น HOLD, เห็นแสง, ไม่ตัน, อยู่ในเกณฑ์ และข้อมูลไม่ขาดช่วง

## ภารกิจ 2 (Target Imaging)

- `M2 GO SUN <offset>`: หันไปที่ "ทิศดวงอาทิตย์ + offset" **แนะนำ** เพราะหาทิศดวงอาทิตย์ใหม่ทุกครั้ง (ใช้จุดตัดศูนย์ที่คำนวณจากค่าสองฝั่ง) ทนการโดนชน/ศูนย์ตัวขับเพี้ยน (ตัวจำลอง: โดนชน 7° แล้วยังคลาด −0.18 ถึง +0.09° ใน 4 seed)
- `M2 GO <มุม>`: หันไปมุมเทียบศูนย์ของตัวขับ (โดนชน 7° = คลาด 7°) เข้าเป้าด้วยการหมุนทิศ `ctl.appr` เสมอ ภาพจึงชี้ตรงกันไม่ว่ามาจากทางไหน
- `M2 SNAP`: ถ่ายตรงนั้นทันที ใช้ได้แม้ภารกิจ 1 ยังล็อกอยู่
- GO จะหยุดภารกิจ 1 ให้เอง (event `E M1 IDLE m2_takeover`)
- ไม่รู้ว่าเป้าอยู่ไหน: เว็บ "สแกนรอบตัว" (ถ่ายทุก ~70% ของมุมรับภาพ) → คลิกภาพที่เห็นเป้า → คลิกที่เป้า → "หันไปถ่ายตรงนี้" (`M2 GO`) หรือ
  "เทียบดวงอาทิตย์" (`M2 GO SUN`) มุมคำนวณจากตำแหน่งในภาพ: 1 pixel ≈ 0.1° ที่ 640 px (ตัวจำลอง: คลิกเป้าแล้วถ่ายใหม่ เป้าอยู่กลางภาพ)
- ภาพกลับหัว/กลับซ้ายขวา: `cam.vflip` / `cam.hmirror` (ปุ่มพลิกในเว็บบันทึกให้) ทุกภาพบอกค่าพลิกของตัวเองใน metadata เว็บคิดทิศให้เอง
- **บอร์ดไม่ยอมถ่าย** (ได้ `J snap_fail` + `E FAULT SNAP ...`) เมื่อ
  - `target_out_of_range`: มุมที่ต้องหันอยู่นอก `act.min..act.max` (หรือเกินระยะ servo)
  - `not_in_tol`: หันได้คลาดเกิน `m2.tol`
  ถ้าจำเป็นต้องได้ภาพจริง ๆ ใช้ `M2 SNAP` ถ่ายตรงที่อยู่แทน
- แสงกล้อง: ปกติกล้องปรับแสงเองระหว่างรอ `m2.settle` ที่มุมเป้า `M2 LOCK` = ตรึงแสงตามภาพตอนนั้น, `M2 UNLOCK` = กลับเป็นอัตโนมัติ
- `err_cmd` ใน metadata = มุมที่สั่งเทียบตัวนับ step **ไม่ใช่มุมจริงที่วัดได้** ความแม่นจริงต้องดูจากภาพ

### กล้องอยู่อีกบอร์ด (เช่น ESP32-CAM AI-Thinker)
firmware ตัวเดียวกันใช้ได้ทั้งสองบอร์ด (compile ผ่านทั้ง ESP32-S3 และ ESP32-CAM):
- บอร์ดหลัก: `SET cam.model 0` ทำภารกิจ 1 และหมุน
- บอร์ดกล้อง: Upload ด้วยบอร์ด "AI Thinker ESP32-CAM" แล้ว `SET act.type 0`, `SET cam.model 4`, `M2 INIT`, `SAVE`
  (GPIO0 เป็นนาฬิกากล้อง ปุ่ม BOOT จึงถูกปิดเอง)
- เปิด NasaSatLab **สองแท็บ** แท็บละพอร์ต: แท็บบอร์ดหลัก `GOTO มุม`/M1 ล็อก แล้วแท็บบอร์ดกล้อง `M2 SNAP`
  (มุมที่คลิกบนภาพของบอร์ดกล้องใช้ไม่ได้ตรง ๆ เพราะบอร์ดกล้องไม่รู้มุมตัวขับ ให้อ่านมุมแล้วพิมพ์ GOTO ในแท็บบอร์ดหลัก)

## ไม่ต่อคอม / ใช้แบต / สื่อสารไร้สาย

| อยากได้ | ตั้งค่า | ผล |
|---|---|---|
| เปิดเครื่องแล้วเริ่มหาแสงเอง | `SET m1.auto 5` แล้ว `SAVE m1.auto` | บูตแล้ว 5 วินาทีเริ่มภารกิจ 1 (`E AUTO ...`) ระหว่างรอกด `STOP` = ยกเลิก ถ้ามีงานอื่นทำอยู่จะไม่แทรก |
| กดปุ่มบนบอร์ดเริ่ม/หยุด | ค่าเริ่ม `hw.btn 0` = ปุ่ม BOOT | กดครั้งแรกเริ่มภารกิจ 1 กดอีกครั้งหยุด (ใช้ปุ่มอื่นต่อลง GND: `SET hw.btn <ขา>`) |
| ดูแบต/ความร้อน (หัวข้อ EPS/OBC) | `SET hw.vbat <ขา ADC>`, `SET hw.vdiv <อัตราส่วน>` | `J hk` ทุก 2 วินาที เว็บแสดงที่หัวจอและแท็บเชื่อมต่อ |
| สั่งงานผ่านวิทยุ serial (HC-12, LoRa UART, XBee) หรือบอร์ดสะพาน | `SET com.baud 9600`, `SET com.rx <ขา>`, `SET com.tx <ขา>`, `SAVE` | ทุกบรรทัดออกทั้ง USB และวิทยุ, รับคำสั่งจากวิทยุได้ ตัวรับอีกฝั่งต่อคอมแล้วใช้ NasaSatLab ได้เลย (telemetry วิทยุ 2 Hz ตาม `com.lhz`, ภาพ 320×240 ≈ 10 s) |

ยังไม่มี Wi-Fi/ESP-NOW ในตัว ถ้าผู้จัดบังคับช่องทางไหน ใช้ช่องที่สองต่อบอร์ดสะพาน หรือให้ AI เขียนเพิ่มตามโค้ด `ops.cpp` (โครง `out::` ส่งทุกบรรทัดไปช่องที่สองอยู่แล้ว)

## สิ่งที่ firmware ป้องกันไว้ (ไม่รายงานว่าผ่านทั้งที่ไม่ผ่าน)

| สถานการณ์ | บอร์ดทำอะไร |
|---|---|
| ADC ตัน | ค่าที่วัด `valid=false`, M1 ไม่ HOLD, ธง SAT ใน telemetry |
| เป้าภารกิจ 2 เกินขอบเขต/ไม่ถึง tol | ไม่ถ่าย + `snap_fail` บอกเหตุผล |
| `M1 START 100`, `M2 GO 500` (เกินช่วงค่าตั้ง) | `ERR RANGE` ไม่ใช้เป้าเก่าเงียบ ๆ |
| `SET` ขาที่ต่อกับ flash/PSRAM (GPIO26–32, 33–37 ถ้า OPI PSRAM), สาย USB (19/20) หรือ UART0 (43/44), ขาที่ไม่มีจริง (22–25), LDR บนขาที่ไม่ใช่ ADC | `ERR PIN <เหตุผล>` ไม่เก็บค่า (ถ้า SAVE ไว้บอร์ดจะพังทุกครั้งที่บูต) |
| ตั้งสองค่าบนขาเดียวกัน | รับค่า แต่ส่ง `E WARN PIN GPIOx ...` เตือน |
| ล็อก (HOLD) แล้วคลาดค้างเกิน `ctl.db` แต่ไม่ถึง `ctl.hys` (หลอดขยับนิดหน่อย, สายดึงในระยะฟรีของเฟือง) | อ่านเกิน `ctl.trim` ครั้งติดกัน → ขยับแก้เล็กน้อยโดยยัง HOLD (`E M1TRIM`) |
| `CAL TH0` แล้วบอร์ดรีเซ็ตก่อน SAVE | ค่าศูนย์ถูกบันทึกลง flash ตั้งแต่ตอนวัดแล้ว |
| กล้องตอบแต่ไม่ส่งภาพ (ขา data/PCLK ผิด) | เลิกรอหลังเฟรมแรกที่หมดเวลา → `E FAULT SNAP no_frames` ไม่ค้างจน watchdog รีเซ็ต |
| `cam.model` ของชิปอื่น (ESP32-CAM บน ESP32-S3 หรือกลับกัน) | ตรวจทุกขาก่อนเริ่มกล้อง → `ERR CAM ... not for this chip` ไม่แตะขา flash/PSRAM (ถ้า SAVE ไว้ก็บูตได้ปกติ) |
| ปิดชดเชย backlash ไปพักหนึ่ง (รัน `BACKLASH` ซ้ำ, เปลี่ยน `act.bl`) | stepper นับ step ชดเชยที่ทำไปแล้ว เปิดกลับมาก็ชดเชยส่วนที่ขาดเอง (เดิมอาจเลื่อนไปทั้ง `act.bl` ตลอด) |
| วิทยุช่องที่สองช้าหรือค้าง | loop ไม่รอวิทยุ บรรทัดที่ไม่มีที่ถูกทิ้งทั้งบรรทัด ภาพรอให้ใส่ได้ทั้งบรรทัด |
| คำสั่งชนกัน | `ERR BUSY <ชื่องาน>` |
| บรรทัดยาวเกิน 2400 ตัว / ขยะหน้าคำสั่ง | `ERR LONG` / ข้ามขยะให้เอง |
| loop ค้างเกิน ~5 วินาที | watchdog รีเซ็ตบอร์ด (ดู `E BOOT TASK_WDT`) |
| ไฟตก | บอร์ดรีเซ็ต ดู `E BOOT BROWNOUT` → ใช้ไฟเลี้ยงมอเตอร์แยก |
| ภาพขาดระหว่างส่ง | tool ขอชิ้นที่หายซ้ำ 3 รอบ ถ้ายังไม่ได้ขึ้น "ภาพเสีย" แล้วใช้งานต่อได้ |

## แก้ปัญหา

| อาการ | สาเหตุที่เป็นไปได้ | ทำอะไร |
|---|---|---|
| เชื่อมต่อแล้วเงียบ | USB CDC On Boot ตั้งผิด / เปิด Serial Monitor ค้าง | ดู `INSTALL_CHECKLIST.md` ข้อ USB, ปิด Serial Monitor |
| บอร์ดรีเซ็ตวน | PSRAM ตั้งผิด (OPI/QSPI) หรือไฟไม่พอ | ลอง PSRAM Disabled, ดู `E BOOT ...` |
| `MOVE` แล้วไม่หมุน | ขา `act.in1..4` ผิด / ไฟ 5V มอเตอร์ไม่มา | ตรวจขา, ไฟ, ไฟ LED บน ULN2003 ต้องกระพริบ |
| หมุนผิดทาง M1 วิ่งหนี | ทิศมอเตอร์กลับ | `SET act.dir -1` |
| หมุนแล้วสะดุด/หลุด step | เร็วเกิน | ลด `act.vmax` (เช่น 25) |
| θ กระโดดมาก | ไฟกระพริบ / สายหลวม / ADC noise | ดู `RAW 1000` ฟิลด์ `th_sd` (บอร์ดเงียบ ~0.15° ต่อหน้าต่าง 20 ms) ถ้าสูงมาก: `sen.win` 40, ตรวจสาย/กราวด์ `ctl.adapt 1` ช่วยให้ยังล็อกได้ |
| ไฟห้องเปลี่ยนแล้วมุมเพี้ยน | แสงรอบข้างเปลี่ยน | ตรวจศูนย์ด้วยท่อเล็ง → `CAL TH0` ใหม่ (อย่าวัด AMB ใหม่อย่างเดียว) มีเวลาค่อยคาลิเบรตใหม่ทั้งชุด |
| M1 ขึ้น `adc_saturated` | แสงแรงเกิน | ถอยหลอด/ปิดกระดาษบางให้เท่ากันสองตัว แล้วคาลิเบรตใหม่ |
| `M2 INIT` ได้ `init fail 0x105` | รุ่นกล้อง/ขาไม่ตรง | ลอง `cam.model` อื่น หรือแก้ `board_config.h` + `cam.model 3` |
| ภาพกลับหัว / กลับซ้ายขวา | การติดตั้งกล้อง | ปุ่มพลิกในแท็บภารกิจ 2 แล้ว "ตรวจทิศภาพ" ใหม่ถ้ายังไม่เคยตรวจ |
| "ตรวจทิศภาพ" ไม่ยอมสรุป | ภาพไม่มีรายละเอียด (ผนังเรียบ/มืด) | หันไปทางที่มีของหลายอย่างหรือมีหลอดอยู่ในภาพ แล้วลองใหม่ |
| ปุ่ม BOOT ไม่ทำอะไร | `hw.btn -1` หรือกล้องใช้ขา 0 (ESP32-CAM) | ดู `J hk` ฟิลด์ `btn` ใช้ปุ่มอื่นต่อลง GND แล้ว `SET hw.btn <ขา>` |
| วิทยุไม่ได้อะไรเลย | `com.baud` ไม่ตรงวิทยุ / สลับ RX-TX | TX ของบอร์ด → RX ของวิทยุ, ตรวจ `E LINK ON ...` และ baud ของวิทยุ |
| compile ไม่ผ่านเพราะกล้อง | ไลบรารีกล้องใน core ไม่ตรง (ไฟล์ปัจจุบัน compile ผ่านกับ core 3.3.5 แล้ว ตรวจก่อนว่าใช้ไฟล์ล่าสุด) | `features.h`: `ENABLE_CAMERA 0` (ภารกิจ 2 จะหายทั้งภารกิจ ใช้เป็นทางสุดท้าย) |
| `ERR PIN ...` ตอน SET ขา | ขานั้นต่อกับ flash/PSRAM/USB หรือไม่ใช่ขา ADC | อ่านเหตุผลท้ายบรรทัด ถ้าบอร์ดไม่มี PSRAM จริงแต่ขาอยู่ช่วง 33–37 ให้ Upload ใหม่ด้วย PSRAM: Disabled |
| ทุกอย่างพัง เวลาเหลือน้อย | — | อัปโหลด `Fallback/Fallback.ino` (ภารกิจ 1 อย่างเดียว) |

## ทดสอบบนคอม (ไม่ต้องมีบอร์ด)

ต้องมี `g++` (MSYS2 MinGW) และ Node.js
```
node host_test/build.js            (firmware หลัก, core 3.x API)
node host_test/e2e.js              (155 ข้อ)
node host_test/build.js --core2    แล้ว  node host_test/e2e.js --core2   (core 2.x API)
node host_test/build.js --esp32    แล้ว  node host_test/camnode_test.js   (ESP32 รุ่นเก่า = บอร์ดกล้อง ESP32-CAM, 15 ข้อ)
node host_test/build.js --fallback แล้ว  node host_test/fallback_test.js  (11 ข้อ)
```
`E2E_SEED=1 node host_test/e2e.js` เปลี่ยน noise ของโลกจำลอง ใช้ดูว่าผลผ่านทุก seed จริง ไม่ใช่ผ่านเพราะโชค (รอบ 1 ต.ค. พบว่า SPR ของโค้ดเดิมผ่านแค่ 1 ใน 4 seed) ตอนนี้ผ่าน seed เริ่มต้น, 1, 2, 3
โลกจำลองมีวิทยุช่องที่สองด้วย (`!LINKIN` ส่งเข้า, `!LINK` คือสิ่งที่วิทยุได้รับ) และปุ่ม BOOT (`!WORLD btnDown 1`)

**compile ด้วย ESP32 core ตัวจริง** (สำคัญที่สุด ตัวทดสอบบนคอมไม่เห็นทุกอย่าง): ต้องมี Arduino IDE 2.x + esp32 core ในเครื่อง
```
node tools/compile_check.js         (NasaSat + Fallback ด้วยค่าบอร์ดที่ใช้บ่อย)
node tools/compile_check.js --all   (+ TinyUSB และบอร์ด ESP32-CAM)
```
ผล 1 ต.ค. 2569 กับ core 3.3.5: ผ่านทั้ง 6 แบบ ไม่มี warning (ก่อนแก้ ทั้ง NasaSat และ Fallback compile ไม่ผ่าน; ชุด 2 เจอชื่อ `link` ชนฟังก์ชัน POSIX
แบบเดียวกับ `stat` แก้แล้ว และตัวทดสอบบนคอมจับชื่อพวกนี้ได้แล้ว)
ตัวทดสอบนี้ compile ไฟล์ firmware จริงทั้งหมดกับ ESP32 API จำลอง แล้วต่อกับ "โลกจำลอง" (หลอด, LDR 2 ตัวที่ γ ไม่เท่ากัน, หน่วงเวลา, ไฟกระพริบ 100 Hz, noise, มอเตอร์ที่หมุนตามสัญญาณขดลวดจริง, backlash, กล้อง) แล้วสั่งงานแบบเดียวกับเว็บ tool ตรวจผลกับค่าจริงที่ซ่อนไว้
**ข้อจำกัด**: compile ด้วย ESP32 core 3.3.5 จริงผ่านแล้ว (`tools/compile_check.js`) แต่ยังไม่ได้ลองกับบอร์ด/มอเตอร์/กล้องจริง ให้ทำตาม `INSTALL_CHECKLIST.md` และ `TEST_PLAN.md`

## สวิตช์ตอน compile (`features.h`)

| ค่า | ปกติ | ใช้เมื่อ |
|---|---|---|
| `ENABLE_CAMERA` | 1 | 0 ถ้าชุดไม่มีกล้องหรือ compile กล้องไม่ผ่าน |
| `ENABLE_SERVO` | 1 | 0 ถ้าไม่ใช้ servo |
| `ENABLE_WDT` | 1 | 0 ชั่วคราวตอนหาสาเหตุบอร์ดรีเซ็ต |
| `ENABLE_LINK` | 1 | 0 ถ้า compile Serial1 ไม่ผ่าน (ช่องที่สองไม่ทำงานจนกว่าจะ `SET com.tx` อยู่แล้ว) |
| `SERIAL_BAUD` | 115200 | บอร์ดที่มีชิป USB-UART ต้องตรงกับที่เลือกใน tool |

เพิ่มหรือแก้ค่าตั้ง: แก้ `tool/src/js/06_cfgdefs.js` แล้ว `node firmware/tools/gen_cfg.js` และ `node tool/build.js` (เว็บกับ firmware จะตรงกันเสมอ)
