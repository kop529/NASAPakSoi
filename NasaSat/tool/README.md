# NasaSat Lab (เว็บ tool ของทีมนาซ่าหน้าปากซอย)

ไฟล์ที่ใช้งานจริงมีไฟล์เดียวคือ **`NasaSatLab.html`** ดับเบิลคลิกเปิดใน **Chrome หรือ Edge** ได้เลย ทำงานออฟไลน์ได้ทั้งหมด ไม่ต้องติดตั้งอะไร และคัดลอกไฟล์นี้ไฟล์เดียวไปเครื่องแข่งได้
ใช้คู่กับ firmware ใน `../firmware` (รายละเอียดบอร์ด, protocol, การติดตั้ง อยู่ที่นั่น)

## ใช้งานเร็ว ๆ
เมนูซ้าย "ลำดับวันแข่ง" เรียงตามที่ทำจริง 1–5 (สี่เหลี่ยมเขียวท้ายชื่อ = ทำแล้ว) และ "เครื่องมือ" (ค่าสด, จูนค่า, หลักฐาน & AI)
1. **1 เชื่อมต่อ**: เลือก "บอร์ดจริง" แล้วเลือกพอร์ต USB ของบอร์ด ถ้าไม่มีบอร์ดเลือก "ตัวจำลอง" เพื่อซ้อม (ตัวจำลองทำงานตามกติกาเดียวกับ firmware จริง)
   ติ๊ก "ต่อใหม่เอง" (ค่าเริ่ม) บอร์ดรีเซ็ต/หลุดแล้วเว็บหาพอร์ตเดิม (VID:PID เดียวกัน) 30 วินาทีแล้วอ่านค่าบอร์ดใหม่ให้ สุขภาพระบบ (`J hk`: อุณหภูมิชิป, หน่วยความจำ, แบต) แสดงที่หน้านี้และแถบบน
2. **2 ฮาร์ดแวร์**: HWID และ PINFIND หาขา LDR (เอามือบังแล้วดูว่าแท่งไหนขยับ)
3. **3 คาลิเบรต**: ทำครบ 8 ขั้น (ลำดับด้านล่าง) ทุกขั้นมีปุ่ม "ถัดไป" Sweep จบแล้วโปรแกรม Fit ให้เอง และขึ้นกล่องตัดสิน ผ่าน / เตือน / ไม่ผ่าน พร้อมเกณฑ์ทีละข้อ
4. **4 ภารกิจ 1**: "เริ่ม" แล้วดูหน้าปัดมุม แถบนับเวลาคงเป้า และกล่องผลรอบล่าสุด ผลในตารางจะ "ผ่าน" ก็ต่อเมื่อคงเป้าได้ต่อเนื่องครบเวลาที่ตั้ง (เริ่มจากปุ่มบนบอร์ดหรือ `m1.auto` ก็นับเป็นรอบ)
5. **5 ภารกิจ 2**: "เตรียมกล้อง" ครั้งแรก (พลิกภาพ → ตรวจทิศภาพ → วัด boresight) แล้วใช้ "เทียบทิศดวงอาทิตย์" + GO (GO หยุดภารกิจ 1 ให้เอง, SNAP ถ่ายได้แม้ภารกิจ 1 ล็อกอยู่) ถ้าบอร์ดไม่ยอมถ่ายจะมีกล่องแดงค้างบอกเหตุผล พร้อมปุ่ม SNAP / เปิดจูนค่า act.min/act.max
   ไม่รู้มุมเป้า: "สแกนรอบตัว" → คลิกภาพที่เห็นเป้า → **คลิกที่เป้าบนภาพ** → "หันไปถ่ายตรงนี้" หรือ "เทียบดวงอาทิตย์" เลือกโฟลเดอร์ให้บันทึกทุกภาพ (.jpg + .json) อัตโนมัติได้
6. **หลักฐาน & AI**: เขียน "อาการ" สั้น ๆ แล้ว "คัดลอกให้ AI" (ปุ่มเดียวกันอยู่ที่แถบบนด้วย) ข้อความมีคำสั่งที่ส่งล่าสุด 20 บรรทัดให้ด้วย
7. ปุ่ม **STOP** (หรือ Space / Esc) หยุดทุกอย่างได้ทุกเมื่อ แม้เพิ่งคลิกปุ่มอื่นไว้ (Space ใช้พิมพ์ได้เฉพาะในช่องพิมพ์ข้อความ)

แถบบนแสดงตลอด: ช่องทาง (แถบสีฟ้าอมเขียว = ตัวจำลอง ไม่ใช่บอร์ดจริง), สถานะภารกิจ 1, งานที่บอร์ดกำลังทำ, θ ตัวใหญ่, error (เฉพาะตอนภารกิจ 1 ทำงาน), มุมตัวขับ, แสงที่เซนเซอร์, ป้าย **"ยังไม่ SAVE n"** (กดแล้ว SAVE ให้), ป้าย **"ปัญหา n"** (error ทุกอันค้างอยู่ในรายการพร้อมวิธีแก้ภาษาไทยจนกว่าจะกด "รับทราบ"), คัดลอกให้ AI, สลับธีมสว่าง/มืด
Console พับไว้เป็นแถบล่าง (เห็นบรรทัดล่าสุด จำนวน error และพิมพ์คำสั่งได้เลย) กด "Console" เพื่อขยาย ติ๊ก "เฉพาะ error" เพื่อกรอง
ปุ่มที่ส่งคำสั่งเข้าบอร์ดมีชื่อคำสั่งต่อท้าย (เช่น `AMB 600`) เอาไปคุยกับ AI หรือกรรมการได้ตรงกัน
ทางลัดสำหรับซ้อม: เปิด `NasaSatLab.html#sim` = ต่อตัวจำลองทันที, เพิ่ม `&tab=m1` (connect/hw/cal/m1/m2/live/tune/ev), `&theme=dark`, `&cmd=M1 START` (หลายคำสั่งคั่นด้วย `;`, `wait 2000` = รอ)

ข้อควรระวัง:
- ก่อน Upload ใน Arduino IDE ต้องกด "ตัดการเชื่อมต่อ" ใน tool ก่อน
- ห้ามเปิด Serial Monitor ของ Arduino พร้อมกับ tool (พอร์ตใช้ได้ทีละโปรแกรม)

## ต่อบอร์ด SunSeek ด้วยบลูทูธ (ไม่ใช้สาย USB)
ใช้ตอนทดสอบควบคุมจริงบนแท่นหมุนด้วยแบตเตอรี่ สาย USB ดึงตัวดาวเทียมไว้ ทำให้ผลการหมุนเพี้ยน
1. **ปิดการเชื่อมต่อของ Ground Station (GS) ของผู้จัดก่อน** (กด Disconnect หรือปิดโปรแกรม GS) บอร์ดต่อบลูทูธได้ทีละโปรแกรมเดียว ถ้า GS ยังต่ออยู่ บอร์ดจะไม่โผล่ในรายการหรือต่อไม่ติด
2. หน้า "เชื่อมต่อ" เลือก **บอร์ดจริง (บลูทูธ / Web Bluetooth)** (ระบบสลับเป็นโหมด SunSeek ให้เอง) กด "เชื่อมต่อ" แล้วเลือก **`SUNSEEK-NasaPakSoi`** ในหน้าต่างของ Chrome ถ้าไม่เห็นชื่อนี้ ติ๊ก "แสดงอุปกรณ์บลูทูธทั้งหมด" แล้วลองใหม่
3. หลังต่อติด ทุกหน้าใช้เหมือนต่อ USB (คำสั่งด่วน, Console, ตรวจทิศ, จูน ADCS, STOP / Space / Esc) บอร์ดส่งข้อมูลทีละบรรทัดต่อหนึ่ง notification
4. หลุด (บอร์ดไกลเกิน, แบตหมด, ไปเปิด GS ต่อแทน): ถ้าติ๊ก "ต่อใหม่เอง" ไว้ เว็บต่อบอร์ดเดิมให้ใหม่ 30 วินาทีโดยไม่ต้องเลือกอุปกรณ์อีก ถ้าไม่สำเร็จกด "เชื่อมต่อ" เอง
ข้อจำกัดที่ต้องรู้: `TEAM_STREAM` (สตรีม `TM,TEAM_T` ที่หน้าตรวจทิศและหน้าคาลิเบรตแบบหมุนมือ) ส่งทาง USB เท่านั้นตามเฟิร์มแวร์ จึงใช้ผ่านบลูทูธไม่ได้ ส่วน `TEAM_CSTREAM` (หน้า "จูน ADCS") ส่งได้ทั้งสองทาง · เปิดได้จากไฟล์ที่ดับเบิลคลิก (file://) ใน Chrome / Edge บนคอมที่มี Bluetooth

## จูน ADCS: ทดสอบ step แล้วอ่านผลเป็นตัวเลข (โหมด SunSeek + เฟิร์มแวร์ทีม)
เมนู "จูน ADCS (SunSeek)" (โผล่เมื่อเลือกโหมด SunSeek หรือบลูทูธ) ใช้ได้ทั้ง USB และบลูทูธ ปุ่ม **STOP ใหญ่ลอยมุมขวาล่างเสมอ** และ Space / Esc ยังหยุดทุกอย่าง (ล้อหยุด กลับ MANUAL หยุดทดสอบ เก็บข้อมูลที่ได้ไว้ในตารางพร้อมหมายเหตุ "หยุดกลางคัน")
1. **พารามิเตอร์**: เว็บอ่าน `TEAM_LIST` ให้เองหลังต่อติด (กด "อ่านค่าจากบอร์ด" ซ้ำได้) แสดง adcs.kp / kd / ki / db / max / kick / kickMs / krate / lock / unlock / lockMs / hgain / srate / sk / ghold / retarget และ rw.slew / minStart / minStable พร้อมช่วงที่บอร์ดรับ ค่าอื่นที่บอร์ดรายงาน (เซนเซอร์แสง, IMU ...) อยู่ในหัวข้อพับ แก้ค่าแล้ว Enter = `TEAM_SET` เข้า RAM ทันที ปุ่ม "บันทึกถาวร" = `TEAM_SAVE` (แถวสีส้ม = ยังไม่ SAVE) แก้ไม่ได้ระหว่างทดสอบ เพื่อให้ตารางตรงกับสิ่งที่รัน
2. **ทดสอบ step**: วางดาวเทียมบนแท่น หันไปทางอื่นก่อนเล็กน้อย กด "เริ่มทดสอบ" เว็บส่งตามลำดับที่เห็นในหัวข้อ "คำสั่งที่เว็บจะส่ง": `STOP` → `ADCS_STRATEGY,REACTION` → `TEAM_CSTREAM,20` → `ADCS_REFERENCE,SUN` → `SET_TARGET,A` → (เริ่มบันทึก) `ADCS_MODE,AUTO` → รอตามเวลาที่ตั้ง → `STOP` → `TEAM_CSTREAM,0`
   - แบบ "ไปที่ A แล้วค้าง": หนึ่งรอบ = หนึ่งแถวในตาราง
   - แบบ "step A → B → A": ไม่ออกจาก AUTO เว็บตั้ง `adcs.retarget = 1` ให้ชั่วคราวแล้วคืนค่า (เวลาแบ่งสามช่วงเท่ากัน แนะนำรวม 36 วินาทีขึ้นไป) ได้สามแถวต่อหนึ่งการทดสอบ (`2.1` = เข้า A, `2.2` = A→B, `2.3` = B→A)
   - ค่าเริ่ม: เกณฑ์ ±2°, นิ่งต้องคงครบ 3 วินาที, บันทึก 20 วินาที ปุ่ม "ดูสด" เปิดสตรีม 10 Hz ไว้ดูมุมโดยไม่สั่งล้อ
3. **กราฟสด/ย้อนหลัง**: มุม (เป้า, EST, ANG + เส้นเกณฑ์ ±), ล้อ (RW, U, I, K), อัตราหมุน GZ คลิกแถวในตารางเพื่อดูกราฟของรอบนั้น
4. **ตารางผล หนึ่งแถวต่อหนึ่ง step**: พารามิเตอร์ที่ใช้ (อ่านจากบอร์ดก่อนเริ่มทุกครั้ง) + ค่าที่ตัวควบคุมรายงานตอนเข้า AUTO (`EVT,TEAM_AUTO`: EST, ANG, KP, KD, KI, SIGN, RSIGN, MAX) · เวลาเข้า ±เกณฑ์ครั้งแรก · เวลานิ่ง (เริ่มอยู่ในเกณฑ์ต่อเนื่องครบเวลาที่ตั้ง) · overshoot (° และ % ของ step วัดหลังเข้าเกณฑ์ครั้งแรก) · error ช่วง 3 วินาทีท้าย (mean ± SD) · max |GZ| · เวลาที่ล้ออยู่ที่ |RW| ≥ adcs.max − 1 (ตัน) · จำนวนครั้งที่เตะ (จาก `EVT,TEAM_KICK`) · **ผิดทิศ** (ใน 0.7 วินาทีแรกมุมเคลื่อนห่างเป้าเกิน 1°) ปรับเกณฑ์/เวลานิ่ง/แหล่งมุม (ANG หรือ EST) ได้ ตารางคำนวณใหม่ให้ทุกแถว "Export ผล (.csv)" ได้ทั้งตาราง (มีพารามิเตอร์ทุกตัวเป็นคอลัมน์ `p.adcs.kp` ...) และ "ข้อมูลดิบรอบที่เลือก (.csv)"
5. บอร์ดอาจส่งคีย์เพิ่มท้ายบรรทัด `TM,TEAM_C` / `EVT,TEAM_*` ในอนาคต เว็บอ่านเป็นคู่ key,value และข้ามคีย์ที่ไม่รู้จัก
ที่ยังไม่ได้ลองกับบอร์ดจริง: ทดสอบด้วยบอร์ดปลอมในเบราว์เซอร์ (ตอบ ACK / EVT / TM,TEAM_C ตามสเปก) และข้อมูลสังเคราะห์ที่คำตอบรู้ล่วงหน้า (สูตรลำดับหนึ่งและลำดับสอง) เท่านั้น

## วิเคราะห์ log ของ Ground Station (ท้ายหน้า "จูน ADCS" หัวข้อ "นำเข้า log GS")
ไฟล์ CSV จาก "START LOG" ของ GS v1.10.x (`timestamp,sun_l,sun_r,sun_ndv,sun_angle_deg,mag_*,gyro_*,rw_cmd`) ใช้ได้โดยไม่ต้องต่อบอร์ด
- หา "รอบ AUTO" จากช่วงที่ `rw_cmd ≠ 0` (ยอมให้ rw = 0 คั่นได้ไม่เกิน 3 วินาที, ตั้งได้) แล้วคิดตัวเลขชุดเดียวกับตาราง step เป้าเริ่มที่ 0° (แก้ได้) ใส่ adcs.max ของตอนนั้นได้ ถ้าเว้นว่างใช้ค่า |rw| ที่มากสุดใน log
- timestamp ละเอียดแค่ 1 วินาที (ราว 25 แถวต่อวินาที): เว็บกระจายแถวในวินาทีเดียวกันให้เท่า ๆ กัน มุมผ่าน median 3 จุด (ตัดค่าสะดุดจุดเดียว) gyro_z ใน log ก่อนแก้เฟิร์มแวร์ผสมสองแหล่งที่เครื่องหมายตรงข้ามกัน จึงใช้แต่ |gyro_z| ใน log ไม่มี TGT, U, I, ข้อมูลเตะ ช่องเหล่านั้นจึงว่าง
- ทดสอบกับ log จริงของ 6 ต.ค. (`newww.csv` ทั้งไฟล์): พบหนึ่งรอบ เริ่ม 15:36:17 ที่ −18.4° ล้อ −40 → **ผิดทิศ** (มุมเคลื่อนห่างเป้า 4.6° ใน 0.7 วินาทีแรก), เข้า ±2° ครั้งแรกที่ 21.0 วินาที (หลังหมุนผ่านไปราว 2 รอบและล้อค้างที่ +40), นิ่งที่ 26.5 วินาที, overshoot +7.3°, error 3 วินาทีท้าย 0.12 ± 0.44°, max |gyro| 236 °/s, ล้ออยู่ที่ ±40 รวม 13.6 วินาที · log ก่อนหน้านั้น (`sunseek_sensor_log.csv`, 15:32:45) พบหนึ่งรอบ 40 วินาทีที่ไม่เคยเข้าเกณฑ์ (มุมค้างราว −19.4° ทั้งที่สั่งล้อ) ไม่ผิดทิศ · ตัวอย่างย่อที่ลบข้อมูลสถานที่ออกแล้ว (ทุกแถวที่ 6 / 8) อยู่ใน `tests/fixtures/`

## ลำดับคาลิเบรตในวันแข่ง (ประมาณ 6–12 นาที)
1. หันเข้าหาหลอดคร่าว ๆ แล้ว `ZERO` (ให้ Sweep ครอบหลอดตรงกลาง)
2. คาลิเบรตขั้น 1 "ตัวขับ": หันเข้าหลอดก่อน (θ ไม่เกิน ±5°) → "วัด backlash" → "ใช้ค่านี้" (ส่ง `SET act.bl` + `SAVE act.bl` ให้); ถ้าหมุนได้ 360° (ระวังสายพัน) เปิดหัวข้อ SPR → `SPR` → "ใช้ค่านี้"
3. ขั้น 2 **ปิดหลอด** → วัดแสงรอบข้าง (บอร์ดรอ LDR นิ่งเอง) **ห้ามข้ามถ้าห้องเปิดไฟ**
4. ขั้น 4 เปิดหลอด → Sweep อัตโนมัติ −60° ถึง 60° ทีละ 5°
5. ขั้น 5 **γ สองระดับแสง** (ทำครั้งเดียวต่อชุด LDR): หันเข้าหาหลอด → "วัดระดับ 1" → เอากระดาษขาว 1–2 ชั้นบังหน้า**หลอด** ห้ามขยับดาวเทียม → "วัดระดับ 2" (แสงต้องลดลงอย่างน้อย 2 เท่า) → เอากระดาษออก
6. ขั้น 5 Fit (ทำให้เองหลัง Sweep): กล่องตัดสินต้องขึ้น "✓ ผ่าน" คือ MAE (+LUT) < 0.3°, error สูงสุด < 1°, γ ซ้าย/ขวา 0.4–0.9, วัดแสงรอบข้างแล้ว, ไม่มีจุด ADC ตัน, ใช้ γ สองระดับแล้ว, ช่วงที่วัดได้แม่นกว้าง ≥ 50° (ตัวเลขละเอียดอยู่ใน "ดูรายละเอียด")
7. ขั้น 6 ตรวจความแม่น (Sweep ตรวจเลื่อนครึ่งช่อง กวาดย้อนทิศ: ถ้า bias เกิน 0.2° แปลว่า LDR หน่วงหรือ backlash ยังชดเชยไม่หมด)
8. ขั้น 7 "ส่งค่า + SAVE"
9. ขั้น 8 หันหน้าดาวเทียมตรงหลอดด้วยของอ้างอิงภายนอก (ท่อเล็ง/โปรแทรกเตอร์/กลางภาพกล้อง) → "ตั้งศูนย์ตรงนี้" (บอร์ดบันทึกค่าศูนย์ลง flash ให้เอง ถ้าเป็น firmware ก่อน 1 ต.ค. ต้องกด SAVE)
10. หน้า ภารกิจ 2 → "เตรียมกล้อง": พลิกบน-ล่าง/ซ้าย-ขวาให้ภาพตั้งตรง → "ตรวจทิศภาพ + มุมรับภาพ" (ให้มีของหรือหลอดในภาพ) → "ล็อกหลอดแล้ววัด boresight" → "ใช้ค่านี้ + SAVE"
    (ต้องทำหลังขั้น 9: boresight วัดเทียบศูนย์ของเซนเซอร์ ถ้าศูนย์ยังผิด ค่าที่ได้ก็ผิดตาม)

ถ้าไฟห้องเปลี่ยน (เปิด/ปิดไฟ ย้ายโต๊ะ): ตรวจศูนย์ด้วยท่อเล็งก่อน ถ้าคลาดเกินเกณฑ์ทำขั้น 8 ใหม่ (30 วินาที) **อย่าวัดแสงรอบข้างใหม่อย่างเดียว และอย่า Fit ใหม่ด้วย Sweep เก่า** (ทดลองแล้วคลาดเพิ่มได้ถึง 3°) ถ้ามีเวลาและไฟเปลี่ยนถาวร ทำขั้น 3–9 ใหม่ทั้งชุด ค่า γ สองระดับใช้ค่าเดิมได้

## ทำไมวิธีของเราแม่นกว่า (สรุปสำหรับตอบกรรมการ)
- LDR สองตัวเอียงออกข้างละ α แต่ละตัวรับแสงตามกฎโคไซน์ จึงได้ D = tan θ · tan α และ θ = atan(D / tan α)
- ค่า ADC จากวงจรแบ่งแรงดันไม่แปรตามแสงตรง ๆ เราแปลงเป็น conductance (G = V/(Vcc−V)) แล้วถอดราก γ ของ LDR แต่ละตัว หักแสงรอบข้างที่วัดตอนปิดหลอด แล้วถอดราก q ของกล่องครอบ
- ความสว่างหลอดหักล้างกันใน D ได้จริงก็ต่อเมื่อเลขชี้กำลังรวมของสองช่องเท่ากัน การ Sweep ที่ความสว่างเดียวแยก γ กับ q ไม่ออก เราจึงวัด**อัตราส่วน γ จากแสงสองระดับ** (กระดาษบังหลอด) แล้วใช้ q เดียวกันทั้งสองช่อง ในตัวจำลอง กล่องครอบสองข้างไม่เท่ากัน หลอดเปลี่ยน 0.5–2 เท่า: วิธีเดิมคลาด 3–4° วิธีนี้คลาด ≤ 0.13°
- ตอนคาลิเบรตเลือกเฉพาะจุดที่หลอดส่องถึงจริง (หักแสงห้องออกก่อนเลือก) จุดตรงขอบกล่องครอบที่แสงหลอดถูกบังจึงไม่ทำให้โมเดลเพี้ยน
- ตาราง LUT แก้ความคลาดที่เหลือ และตั้งศูนย์สัมบูรณ์กับของอ้างอิงภายนอก
- ผลจากการจำลอง (firmware C++ ตัวจริงกับโลกจำลอง, ดู `../firmware/TEST_PLAN.md`):
  - หลังคาลิเบรตครบ มุมคลาดจากค่าจริง MAE 0.04° สูงสุด 0.10°
  - ห้องเปิดไฟสว่าง 30% ของหลอด + กล่องครอบไม่เท่ากัน หลอดเปลี่ยน 0.5–1.8 เท่า ยังคลาด 0.09° (ไม่วัด γ สองระดับ: 3.3–3.6°, ข้ามการวัดแสงรอบข้าง: 5–15°)
  - วิธี atan(D ดิบ) × k คลาด 4–8° เมื่อหลอดสว่างเปลี่ยน
  - **เป็นผลจำลอง ของจริงต้องวัดซ้ำกับของอ้างอิงภายนอก**

## Protocol
สรุปอยู่ที่ `../firmware/PROTOCOL.md` (คำสั่ง, คำตอบ, JSON ทุกชนิด, event, การส่งภาพ) และค่าตั้งทั้งหมดที่ `../firmware/CONFIG_KEYS.md`
สิ่งที่เว็บทำเพิ่มเอง: ขอชิ้นภาพที่หายซ้ำสูงสุด 3 รอบ (ขาดถาวร = รายงานภาพเสียแล้วใช้งานต่อได้), ตัดจุด sweep ที่ ADC ตันออกจากการ Fit, ตัดสินภารกิจ 1 จากทุก sample ในช่วงคงเป้า, ต่อใหม่เองเมื่อบอร์ดหลุด, อ่านค่าบอร์ดใหม่หลัง `E BOOT`, แปลงตำแหน่งบนภาพเป็นมุม (`img_meta`: cam_az_cmd, hm, cam_dir, hfov)

ตัวจำลองในเว็บ: กล้องติดกลับหัว 180° โดยตั้งใจ (ฝึกพลิกภาพและตรวจทิศภาพ), มีปุ่ม "กดปุ่ม BOOT บนบอร์ด", เริ่มภารกิจ 1 เองตาม `m1.auto` หลัง Reboot, ส่ง `J hk`

สิ่งที่ยังไม่ได้ทดสอบ: การต่อบอร์ดจริงผ่าน Web Serial รวมถึงการต่อใหม่อัตโนมัติ (ยังไม่มีบอร์ด) ตรวจแล้วแค่ว่า Chrome บนเครื่องนี้เปิด Web Serial จากไฟล์ที่ดับเบิลคลิกได้, การเลือกโฟลเดอร์บันทึกภาพ (ต้องกดเลือกเอง ทดสอบอัตโนมัติไม่ได้)
