# ตอบรีวิวความพร้อม (24 ก.ย. 2569)

รีวิวถูกต้องและมีประโยชน์มาก ข้อ P1 ทั้ง 4 ข้อเป็นบั๊กจริง แก้แล้วทั้งหมด และข้อพบเพิ่มเติมข้อ 5 (bias ของ `phi`) ตรงกับที่ชุดทดสอบใหม่ของ firmware จับได้พร้อมกัน
หลักฐานทุกข้อรันซ้ำได้: `node tool/tests/run_tests.js` (55/55), `node firmware/host_test/build.js && node firmware/host_test/e2e.js` (106/106, core 3.x และ `--core2` 106/106), `build.js --fallback && fallback_test.js` (11/11)

## P1

| ข้อ | แก้อย่างไร | ทดสอบที่พิสูจน์ |
|---|---|---|
| 1 M2 ถ่ายทั้งที่ไปไม่ถึงเป้า | ก่อนถ่ายตรวจว่าไปถึงได้ (`act.min/max` และระยะ servo) และหลังหมุนตรวจ `|err_cmd| ≤ m2.tol` ถ้าไม่ผ่าน**ไม่ถ่าย** ส่ง `J snap_fail {reason,...}` + `E FAULT SNAP reason` เว็บขึ้นเหตุผลเป็นภาษาไทย; `M2 GO 500` / `M1 START 100` (เกินช่วงค่าตั้ง) ได้ `ERR RANGE` แทนการใช้เป้าเก่าเงียบ ๆ | e2e: "target outside act.min..act.max -> snap_fail, no photo", "pointing error > m2.tol -> snap_fail not_in_tol", "... -> ERR RANGE"; run_tests: ตัวจำลองในเว็บทำเหมือนกัน |
| 2 ADC ตันแล้ว HOLD | ค่าที่ตัน (sen.topo 0: ≥ 3050 mV, topo 1: ≤ 60 mV) ถูกตั้ง `valid=false` เสมอ M1 จึงไม่ล็อก ขึ้น `E M1 LOST adc_saturated` / `SEARCH adc_saturated`, SEARCH ข้ามจุดที่ตัน, AMB/BAL ปฏิเสธค่าที่ตัน, RAW/sweep_pt มีฟิลด์ `sat`, Fit ตัดจุดที่ตันออก, เว็บเตือนวิธีแก้ | e2e: "clipped ADC: M1 never declares HOLD" (หลอดแรง 60 เท่า 25 วินาทีไม่ HOLD), "reason reported", "telemetry SAT flag", "light back to normal -> M1 recovers"; Fallback ก็ทำเหมือนกัน |
| 3 servo 16 บิต | ใช้ 14 บิต (`SERVO_BITS`) ตรวจผล attach ถ้าล้มขึ้น `E FAULT ACT servo_pwm_attach_failed` และ HWID บอก "servo (PWM not attached)"; core 2.x ตรวจผล `ledcSetup` ด้วย; mock เข้มแบบชิปจริง (สูงสุด 14 บิต, 8 ช่อง, freq×2^bits ≤ 80 MHz) | e2e ทั้ง core 3.x และ 2.x: "servo PWM attached at 14 bit (accepted by the strict ESP32-S3 LEDC mock)", "M1 with a servo still locks" |
| 4 ภาพขาดแล้ว exception | เขียนตัวประกอบภาพใหม่: ถอดรหัสทีละชิ้นตอนรับ (ชิ้นเสีย = ขาด), ไม่ใช้ array ที่มีช่องว่าง, ครบ 3 รอบแล้วจบเป็น `ok:false` พร้อมจำนวนชิ้นที่ขาด, มี `poll()` จบภาพที่ `IMG E` หาย; ตัวอ่าน serial และตัวแยกบรรทัดในเว็บครอบ try/catch ไม่ให้บั๊ก UI หยุดการอ่าน | run_tests: 6 ข้อ (ขาดแล้วขอซ้ำ, ขาดถาวร, base64 เสีย, IMG E หาย, ใช้งานต่อได้); e2e: สายทำชิ้นหายจริงระหว่างส่งจาก firmware C++ |

## ข้อพบเพิ่มเติม

| ข้อ | สถานะ |
|---|---|
| 1 "ผ่าน" ไม่พิสูจน์การคงเป้า | แก้: ย้ายเกณฑ์ไป `NS.m1Judge` (ทดสอบได้) ทุก sample ในช่วงคงเป้า (ตั้งได้ ค่าเริ่ม 3 s) ต้อง HOLD, valid, ไม่ตัน, อยู่ในเกณฑ์, ข้อมูลขาดไม่เกิน 0.5 s (รวมกรณีข้อมูลหยุดไหล) และ sample ≥ 80% ตารางแสดง |error| สูงสุด, จำนวน sample และเหตุผลที่ไม่ผ่าน (run_tests 8 ข้อ) |
| 2 M1 → ถ่ายภาพสะดุด | แก้: `M2 SNAP` ใช้ช่องงานเสริม ถ่ายได้ขณะ M1 ล็อก (สำหรับวัด boresight) และ `M2 GO` หยุด M1 ให้เอง (`E M1 IDLE m2_takeover`) (e2e 2 ข้อ) |
| 3 ไม่บังคับล็อกแสงก่อนถ่าย | ปรับ: ระหว่างรอ `m2.settle` ที่มุมเป้า กล้องถ่ายทิ้งต่อเนื่องให้ auto exposure ปรับกับภาพเป้าจริง, `M2 LOCK` ยังใช้ตรึงแสงได้, metadata บอกสถานะเสมอ (ไม่บังคับ เพราะโจทย์จริงยังไม่รู้) |
| 4 err_cmd ไม่ใช่ error จริง | แก้ป้ายในเว็บ: "err_cmd (คำสั่ง − ตัวนับ step ไม่ใช่มุมจริงที่วัด)", เอกสาร PROTOCOL/README ระบุชัด; e2e ตัดสินภารกิจ 2 จากมุมกล้องจริงที่ฝังในภาพจำลอง |
| 5 bias ของ phi | ยืนยันและแก้: ในโลกจำลอง Sweep+Fit เหลือค่าคงที่ −0.37° (กระจายแค่ 0.06°) ที่ขั้นตรวจของเว็บมองไม่เห็น เพิ่ม `CAL TH0 ref` + ขั้นที่ 8 ในเว็บ (ตั้งศูนย์กับของอ้างอิงภายนอก) หลังทำเหลือ MAE 0.04° ตรวจจากทั้งสองทิศหมุน, TEST_PLAN B7 กำหนดให้วัดกับโปรแทรกเตอร์ |
| JS ambient 0.08 ไม่มี assertion | เพิ่ม assertion ทั้งกรณีไม่วัด AMB ใหม่ (แย่ลงแต่ยังดีกว่าวิธีดิบ, บันทึกไว้) และกรณีวัด AMB ใหม่ (MAE < 0.4) ระหว่างนั้นพบปัญหาใหญ่กว่า: ห้องสว่าง 30% ของหลอด การ fit เดิมคลาด 8–22° สาเหตุ (ทดลองแยกแล้ว) คือการเลือกจุด fit นับแสงห้องเป็นแสงหลอด จึงเอาจุดขอบกล่องครอบที่หลอดถูกบังมา fit แก้เป็นหักแสงรอบข้างก่อนเลือกจุด เหลือ 0.25–0.3° เพิ่ม γ แยกแต่ละ LDR (`est.gammaR`) ด้วย ซึ่งช่วยเพิ่มอีกเล็กน้อย (~0.02–0.03°) e2e ของ firmware ในห้องสว่างคลาด 0.09° ทั้งหลอด 0.5×, 1×, 1.8× |
| AMB วัดทันทีหลังปิดหลอด | (พบระหว่างแก้) LDR ยังค่อย ๆ มืดลง ทำให้ประเมินแสงรอบข้างสูงเกิน 35% firmware รอจนค่านิ่งเอง (e2e: คลาด 0.01%) |

## ยังไม่ได้ทำ (ตามที่รีวิวชี้)
- build ด้วย ESP32 SDK จริง: เครื่องนี้ห้ามติดตั้ง ต้องทำบนเครื่องแข่งตาม `firmware/INSTALL_CHECKLIST.md` ข้อ 4 (ทำได้ก่อนมีบอร์ด)
- ทดสอบกับฮาร์ดแวร์จริง, ไฟเลี้ยง/brownout: แผนอยู่ใน `firmware/TEST_PLAN.md` ส่วน B
- สื่อสารไร้สาย (GsBridge/ESP-NOW/Wi-Fi), บอร์ดกล้องแยก, DC motor/reaction wheel: ยังไม่ทำ รอข้อมูลโจทย์ ถ้าผู้จัดยืนยันว่าต้องใช้ จะยกเป็นงานถัดไปทันที
- งานกล้องใน task แยก: วัดแล้วว่า loop ยาวสุด ~290 ms ตอนส่งภาพผ่าน UART และ STOP ตอบภายใน 20 ms จึงยังไม่แยก
- เอกสารทฤษฎี + คู่มือหน้างาน (ชิ้นที่ 3): ยังไม่เริ่ม จะเขียนใหม่ ไม่ใช้เอกสาร ADCS เดิมที่ซ้ำ
