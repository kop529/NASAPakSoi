## 0. สรุปสั้นที่สุด (ถ้าอ่านได้หน้าเดียว)

1. ปัญหาหลักไม่ใช่ "สีไม่สวย" แต่คือ**ทุกอย่างมีน้ำหนักเท่ากัน**: 8 แท็บเท่ากัน, ทุกกล่องเป็นการ์ดขอบมนเหมือนกัน, ปุ่มหน้าตาเหมือนกัน, สีฟ้าตัวเดียวใช้ทั้งปุ่มหลัก แท็บที่เลือก ขั้นที่เลือก แท่ง PINFIND และเส้นกราฟ จึงดูเหมือน "หน้าที่ AI สร้างจาก component สำเร็จรูป" และไม่บอกว่า**ต้องทำอะไรต่อ**
2. สิ่งที่ต้องเห็นตลอดเวลา (ต่อจริงหรือจำลอง, บอร์ดกำลังทำงานอะไร, θ, มีค่ายังไม่ SAVE, error ล่าสุด, STOP) ตอนนี้มีครบแค่ครึ่งเดียว และ error หายไปใน 3.5 วินาที
3. มีบั๊กด้านความปลอดภัยที่หน้าจอ: **กด Space หลังคลิกปุ่มใด ๆ จะ "กดปุ่มนั้นซ้ำ" แทนการ STOP** (เช่นกด START แล้วกด Space = START ซ้ำ) `09_app.js:667-671`
4. ขั้นคาลิเบรต 8 ขั้นในเว็บ**ไม่ตรง**กับ 8 ขั้นในคู่มือ (คู่มือมี ZERO, BACKLASH แต่เว็บไม่มีปุ่ม BACKLASH/SPR/M2 INIT เลย) และไม่มีขั้นไหนบอกผ่าน/ไม่ผ่านเอง
5. ทางแก้: โครงใหม่ = แถบสถานะด้านบนคงที่ + แถบขั้นตอนวันแข่งด้านซ้ายที่มีสถานะ ✓/!/✗ + พื้นที่ทำงาน + คอนโซลพับได้ด้านล่าง, คาลิเบรตเป็น wizard ที่ตรวจเองและบอก "ถัดไป", ภาษาภาพแบบแผงเครื่องมือวัด (เทาเป็นหลัก สีใช้เฉพาะสถานะผิดปกติ ตัวเลขใหญ่ฟอนต์ mono) ตามแนว ISA-101 / ห้องควบคุม
6. ทำได้ 2 ระดับ: **ฉบับขั้นต่ำ 1 วัน** (แก้ของที่เจ็บที่สุด ไม่ย้ายโครง) และ **ฉบับเต็ม 3–4 วัน** กำหนดเสร็จไม่เกิน 4 ต.ค. แล้ว**หยุดแก้ UI** เก็บไฟล์เก่าไว้เป็นสำรองเสมอ

### 1.2 ปัญหาการใช้งาน (สำคัญกว่าหน้าตา)

**ก. ไม่รู้ว่าต้องทำอะไรต่อ**

- **ขั้นในเว็บไม่ตรงคู่มือ**: README/Playbook บอก ZERO → BACKLASH (→ SPR) → AMB → Sweep → Fit → ตรวจ → ส่ง → TH0 แต่เว็บมี "1 ตั้งค่า, 2 แสงรอบข้าง, 3 Balance, 4 Sweep …" ZERO อยู่ในแท็บค่าสด, BACKLASH/SPR/`M2 INIT`/`M2 MANUAL`/`CAL CLR` **ไม่มีปุ่มที่ไหนเลย** ต้องพิมพ์ในคอนโซล (ยืนยันด้วย grep ใน `index.html`, `09_app.js`) ผล BACKLASH ขึ้น toast "ตั้ง act.bl ได้ในแท็บจูนค่า" (`09_app.js:184`) = ต้องจำตัวเลขแล้วไปพิมพ์เอง

**ข. ไม่มีการตัดสินผ่าน/ไม่ผ่านให้**

- ภารกิจ 1: tile "ผล (±1°)" คือค่าขณะนั้น (`09_app.js:282`) ไม่ใช่ผลตัดสินจริงของ `NS.m1Judge` ซึ่งอยู่ในตาราง**ใต้ขอบจอ** ที่ 1366×768 (S19) จึงอาจเห็น "ผ่าน" สีเขียวใหญ่ ขณะที่ตารางบอก "ไม่ผ่าน" ไม่มีตัวนับเวลาคงเป้า 3 วินาที

**จ. ความปลอดภัยและคีย์ลัด**

## 2. หลักการออกแบบสำหรับเครื่องมือนี้

**ผู้ใช้**: นักเรียน ม.ปลาย 3 คน (A คุมคีย์บอร์ด, B ฮาร์ดแวร์, C จดบันทึก) ใช้แล็ปท็อปจอ 1366×768 หรือ 1920×1080 ในห้องโรงแรมที่สว่าง อาจยืนดูจากระยะ 1 เมตร เวลาจำกัด 3 ชั่วโมง ฮาร์ดแวร์ไม่รู้ล่วงหน้า และวนลูป "วัด → วางให้ AI → แก้ค่า → ทดสอบ" ตลอด

หลัก 8 ข้อ (ใช้ตัดสินทุกการออกแบบ):

1. **สถานะก่อนการกระทำ** ทุกหน้าจอต้องตอบ 5 คำถามโดยไม่ต้องเลื่อน: ต่ออะไรอยู่ (จริง/จำลอง), บอร์ดกำลังทำอะไร, θ เท่าไร, มีอะไรยังไม่ SAVE, ปัญหาล่าสุดคืออะไร
2. **หนึ่งหน้าจอ หนึ่งปุ่มหลัก** ปุ่มเติมสีมีได้ตัวเดียวต่อพื้นที่งาน (ยกเว้น STOP ที่อยู่นอกพื้นที่งาน)
3. **สีคือสัญญาณ ไม่ใช่ของตกแต่ง** (ISA-101) ปกติ = เทา, กำลังทำ = ฟ้า, ต้องระวัง = เหลืองอำพัน, ผิด = แดง, ผ่าน = เขียว และทุกสีต้องมีข้อความหรือไอคอนกำกับ (ตาบอดสีอ่านได้)
4. **ระบบตัดสินให้ คนตัดสินใจ** ทุกขั้นที่มีเกณฑ์ (Fit, ตรวจ, M1, boresight) ต้องแสดงคำตัดสิน ผ่าน/เตือน/ไม่ผ่าน พร้อมเหตุผลบรรทัดเดียว ตัวเลขละเอียดพับไว้
5. **error ต้องอยู่จนกว่าคนจะเห็น** และบอกวิธีแก้เป็นภาษาไทยจากตาราง cheatsheet
6. **ทุกปุ่มบอกคำสั่งที่ส่ง** ใต้ชื่อปุ่มหรือใน tooltip แสดง `AMB 600`, `SWEEP -60 60 5 300 cal` เป็นตัว mono เล็ก ๆ ทีมจะพูดกับ AI และกรรมการด้วยภาษาเดียวกับ protocol
7. **ความผิดพลาดที่แก้ไม่ได้ต้องยาก** DEFAULTS, ล้างข้อมูล sweep, Reboot อยู่ในเมนู "…" หรือหมวดขั้นสูง มีข้อความยืนยันในหน้า (ไม่ใช่ `confirm()`)
8. **ออฟไลน์ ไฟล์เดียว เร็ว** ไม่มี CDN ไม่มี animation ประดับ ไอคอน SVG inline ฟอนต์ระบบ

**สิ่งที่ต้องเห็นตลอดเวลา** (แถบสถานะบน สูง 48px ไม่เลื่อนตาม):
- ช่องทาง: `บอร์ดจริง COM · 115200` หรือ `ตัวจำลอง` (แถบลายทแยงสีฟ้าอมเขียวทั้งแถบ ให้รู้ตัวเสมอว่าเป็นจำลอง) หรือ `ไม่ได้เชื่อมต่อ` / `หลุด!` (แดง)
- สถานะบอร์ด: M1 (พัก / ค้นหา / ปรับ / ล็อก 2.4 s / หาไม่เจอ) + งานที่รัน (`SWEEP 12/25`, `AMB`, `BACKLASH`, `SNAP #3`)
- θ ตัวใหญ่ mono, err เฉพาะเมื่อ M1 ทำงาน, มุมตัวขับ, แสง (เห็น / ไม่เห็น / **ADC ตัน**)
- `ยังไม่ SAVE 3 ค่า` (คลิกแล้ว SAVE ได้เลย)
- ปัญหาล่าสุด (ชิปสีแดงพร้อมจำนวน คลิกเปิดคอนโซลกรองเฉพาะ error)
- ปุ่ม `คัดลอกให้ AI` และ STOP

### 3.4 คาลิเบรตเป็น wizard จริง

แต่ละขั้นมีโครงเดียวกัน: **ต้องทำอะไร (1 บรรทัด)** → **ตรวจก่อนเริ่ม (อัตโนมัติ)** → **ปุ่มหลัก + คำสั่งที่ส่ง** → **ผล + คำตัดสิน** → **ถัดไป** (เปิดเมื่อผ่าน หรือ "ข้ามไป (ไม่แนะนำ)" เป็นลิงก์ตัวเล็ก)

| ขั้น | ชื่อ | ตรวจก่อนเริ่ม | คำสั่ง | เกณฑ์ผ่าน (แสดงเป็นรายการ ✓/!/✗) |

### 3.5 คอนโซลและ "คัดลอกให้ AI" รวมเป็นลูปเดียว

- คอนโซลอยู่ล่าง **พับเป็นค่าเริ่ม** (แถบ 32px แสดงบรรทัดล่าสุด + จำนวน error + ช่องพิมพ์ย่อ) คลิกหรือกด `` Ctrl+` `` ขยายเป็น 40% ของความสูง ลากปรับได้ (จำใน localStorage)
- ช่องพิมพ์คำสั่งอยู่ในแถบพับด้วย กด `/` จากที่ไหนก็ได้เพื่อโฟกัส (ยกเว้นอยู่ในช่องกรอก)
- ตัวกรองแบบปุ่มกลุ่ม: ทั้งหมด · คำสั่ง · error/event · telemetry; ชิปคำสั่งด่วน HELLO / DIAG / CFG LIST / HELP / RAW อยู่ในแถบเครื่องมือของคอนโซล
- ปุ่ม **คัดลอกให้ AI** อยู่ในแถบสถานะบนตลอดเวลา กดแล้วเปิดแผงเล็ก (ไม่เปลี่ยนหน้า):

```
┌ คัดลอกให้ AI ────────────────────────────────────────────── ✕ ┐
│ อาการ: [ภารกิจ 1 ล็อกแล้วแต่วัดด้วยท่อเล็งคลาด 1.2° ไปทางซ้าย   ] │
│ แม่แบบ: [มุมคลาดคงที่] [แกว่งไม่หยุด] [ไม่ล็อก] [ภาพเบลอ] [compile] │
│ ใส่: ☑ สถานะ+ค่าตั้ง ☑ ผลคาลิเบรต ☑ telemetry 10 s ☑ error ล่าสุด     │
│      ☑ คำสั่ง 20 บรรทัดล่าสุด ☐ DIAG ใหม่ (ส่ง DIAG ก่อน)            │
│ ┌ ตัวอย่าง (2,140 ตัวอักษร) ──────────────────────────────────┐ │
│ │ # NasaSat context …                                           │ │
│ └───────────────────────────────────────────────────────────────┘ │
│                                      [DIAG + คัดลอก]  [คัดลอก]    │
└───────────────────────────────────────────────────────────────────┘
```
แม่แบบอาการเติมประโยค "คาดว่า … แต่ได้ … ลองแล้ว …" ตาม Playbook ข้อ 9 ข้อ 3 และ pack ควรมี **คำสั่งที่ส่งล่าสุด** (ตอนนี้มีแค่ error/event `09_app.js:602`) เพื่อให้ AI เห็นว่าทีมทำอะไรไปแล้ว

### 3.6 error ที่ไม่หาย

- toast ใช้เฉพาะข่าวดีสั้น ๆ ("SAVE แล้ว") และหายเอง
- ERR / FAULT / snap_fail / หลุดการเชื่อมต่อ / BOOT BROWNOUT → เข้า **ถาดปัญหา** (ชิป `⚠ 2` บนแถบสถาน) และแสดงเป็นแถบในหน้าที่เกี่ยวข้อง (inline) จนกว่าจะกด "รับทราบ"
- แปลรหัสเป็นวิธีแก้ด้วยตารางเดียว (ย้ายจาก cheatsheet มาเป็นข้อมูล JS ที่ทดสอบได้):
  `BUSY X` → "บอร์ดกำลังทำ X อยู่: รอให้จบ หรือกด STOP" · `RANGE k a..b` → "ค่าต้องอยู่ระหว่าง a ถึง b" · `STATE` → "ต้องอยู่ในสถานะ HOLD ก่อน" · `CAM` → "กล้องไม่พร้อม: ลอง cam.model อื่นแล้วกด เริ่มกล้อง (M2 INIT)" · `adc_saturated` → วิธีแก้ 3 ข้อ · `BOOT BROWNOUT` → "ไฟไม่พอ: act.hold 0, hub มีไฟ" · `target_out_of_range` → "ขยาย act.min/act.max หรือใช้ SNAP" ฯลฯ

## 4. ระบบภาพ (Visual Design System)

### 4.1 ทิศทาง

"แผงเครื่องมือวัดในห้องแล็บ" ไม่ใช่ "SaaS dashboard": พื้นเรียบสีเทา ไม่มีเงา ไม่มี gradient มุมโค้งเล็ก (4px) ส่วนต่าง ๆ แบ่งด้วยเส้นคั่นและหัวข้อ ไม่ใช่การ์ดซ้อน ตัวเลขเป็นพระเอก (ใหญ่ mono ตัวเลขกว้างเท่ากัน) สีมีความหมายตายตัว มีภาพที่เป็นของโดเมนเราหนึ่งชิ้น: **หน้าปัดมุม** (ข้อ 4.7)

ค่าเริ่มของธีม: ตาม `prefers-color-scheme` ของเครื่อง มีปุ่มสลับ สว่าง/มืด บนแถบสถานะ จำใน localStorage **แนะนำใช้ธีมสว่างในห้องแข่ง** (ห้องโรงแรมสว่าง จอแล็ปท็อปสะท้อนแสง) ธีมมืดใช้ตอนซ้อมกลางคืน

### 4.4 ระยะห่างและโครง

- สเกล 4px: 4, 8, 12, 16, 24, 32
- ความสูงปุ่ม/ช่องกรอก 36px (STOP 40px สูง กว้าง ≥ 112px) พื้นที่คลิกขั้นต่ำ 32px
- มุมโค้ง 4px ทุกอย่าง (ปุ่ม, ช่องกรอก, ป้ายสถานะ 999px ได้เฉพาะชิป) เลิกใช้ 8px
- **ไม่มีเงา** ยกเว้นแผงลอย (แผง AI, เมนู) ใช้ `0 8px 24px rgb(0 0 0 / .18)`
- พื้นที่งาน: หัวหน้า → เส้นคั่น → ส่วนย่อยคั่นด้วยหัวข้อ 15px + ระยะ 24px ไม่ครอบการ์ด ใช้กล่องขอบเฉพาะสิ่งที่เป็น "วัตถุ" จริง (กราฟ, ภาพ, ตาราง, แผงคำตัดสิน)

### 4.5 ชิ้นส่วน (components)

**ปุ่ม 5 ระดับ**
| ชนิด | หน้าตา | ใช้ |
|---|---|---|
| หลัก | เติม `--accent` ตัวขาว | 1 ตัวต่อหน้า/ขั้น เช่น "เริ่มกวาดมุม" |
| รอง | ขอบ `--line-strong` พื้น surface | ทางเลือก เช่น "ส่งออก CSV" |

| STOP | เติม `--stop` ตัวขาว หนา 700 มีไอคอนสี่เหลี่ยม และข้อความ `Space / Esc` เล็กข้างใต้ | ที่เดียวบนแถบสถานะ |

ปุ่มที่ส่งคำสั่งแสดงคำสั่งเป็นบรรทัดที่สอง mono 11px `--muted` เช่น
```
┌──────────────────────┐
│  วัดแสงรอบข้าง        │
│  AMB 600             │
└──────────────────────┘
```
ระหว่างรอคำตอบ ปุ่มนั้นเป็น `กำลังทำ…` + ปิดการกด (กันกดซ้ำ ซึ่งตอนนี้ได้ `ERR BUSY`)

**ป้ายสถานะ (status pill)**: ข้อความ + ไอคอนเสมอ ไม่มีจุดลอย ๆ ไร้ป้าย เช่น `■ พัก`, `◐ กำลังปรับ`, `✓ ล็อก 2.4 s`, `✕ หาไม่เจอ`

**ค่าตัวเลข (readout)**: ป้าย 13px `--muted` บน, ตัวเลข mono บน baseline เดียวกับหน่วย, ถ้าไม่มีข้อมูลแสดง `—` สีจาง (ไม่ใช่ `--`) ห้ามใส่กรอบสีให้ค่าปกติ

**แผงคำตัดสิน (verdict)** ใช้ในทุกขั้นที่มีเกณฑ์:
```
┌───────────────────────────────────────────────────────────────┐
│ ✓ ผ่าน — โมเดลแม่นพอใช้แข่ง                                    │ ← แถบซ้ายหนา 4px สี ok
│   ✓ MAE (โมเดล+LUT) 0.028°   เกณฑ์ < 0.3°                      │
│   ✓ คลาดสูงสุด 0.333°        เกณฑ์ < 1°                        │
│   ✓ γ ซ้าย/ขวา 0.599 / 0.596  เกณฑ์ 0.4–0.9                    │
│   ✓ แสงห้องจากการวัดขั้น C4                                     │
│   ! ช่วงแม่น −35°…+40° (แคบกว่า ±45°)                           │
└───────────────────────────────────────────────────────────────┘
```
(หนึ่งในสามสถานะ ผ่าน/เตือน/ไม่ผ่าน ทั้งแผงใช้ `--*-bg` จาง ๆ ไม่ใช้กรอบสีทั้งกล่อง)

**ตาราง**: หัวตาราง 13px `--muted` ตัวเลขชิดขวา mono แถวสูง 32px แถวที่ดีที่สุดใช้ตัวหนา + ✓ (ไม่เปลี่ยนทั้งแถวเป็นสีเขียว)

**ช่องกรอกค่าตั้ง**: ช่องกรอกกับหน่วยติดกันเป็นชิ้นเดียว `[ 0.85 | ]` `[ 150 | ms ]` สถานะ: ปกติ / แก้แล้วยังไม่ส่ง (ขอบ accent) / ส่งแล้วยังไม่ SAVE (แถบซ้ายอำพัน) / ผิดช่วง (ขอบแดง + ข้อความ "0.1–1.5")

### 4.6 กราฟ (`08_charts.js`)

- สีทุกอย่างอ่านจาก CSS token ตอนวาด (มี `NS.cssVar` อยู่แล้ว `08_charts.js:3`) รวมสีเส้น: ส่ง `color: 'var:--ch-l'` แล้วแปลงตอนวาด เพื่อให้เปลี่ยนธีมแล้วกราฟเปลี่ยนตาม (ตอนนี้สีเส้นตายตัว `09_app.js:6`) และตั้ง `dirty = true` ทุกกราฟเมื่อสลับธีม
- เส้นหนา 1.5px (ข้อมูลหลัก 2px), จุด r=3 ขอบ 1.5px สีพื้น
- เส้นตาราง `--line` ความทึบ 1 (ไม่ใช้ globalAlpha) เส้นศูนย์ `--line-strong`
- ป้ายแกน 11px mono `--muted`; หน่วยของแกน y เขียนที่มุมบนซ้ายครั้งเดียว; ลบคำว่า "แกนนอน:" (`08_charts.js:199`) เขียนหน่วยแกน x ที่มุมขวาล่าง
- legend ย้ายออกจาก canvas เป็น HTML เหนือกราฟ (ใช้ฟอนต์ไทยจริง, คลิกซ่อนเส้นได้, แสดงค่าล่าสุด mono) — ถ้าเวลาไม่พอ คงใน canvas แต่ใช้ฟอนต์ token
- สถานะว่าง: ข้อความกลางกราฟ "ยังไม่มีข้อมูล — กด เริ่มกวาดมุม" แทนแกน −1..1
- จุดที่ ADC ตัน: วาดเป็นวงกลมกลวงสีแดง + ใส่ใน legend "ตัด N จุด (ADC ตัน)"
- ความสูงกราฟตามพื้นที่ ไม่ใช่ 220px ตายตัว (`style.css:122`) ใช้ `clamp(180px, 32vh, 320px)`

### 4.7 หน้าปัดมุม (ชิ้นเดียวที่ทำให้เครื่องมือ "เป็นของเรา")

SVG ครึ่งวงกลม −90°…+90° วาดใหม่ทุก 100 ms จาก telemetry: แกนหน้าดาวเทียม (เส้นตั้งตรง), ทิศแสง θ (เส้น ink + วงกลมเล็ก), เป้า m1.tgt (เส้นประ), ลิ่ม ±tol (`--ok-bg`), ช่วงมุมแม่นจากผล Fit (ส่วนโค้งเทาเข้ม) ใช้ในหน้าภารกิจ 1, ขั้น C2, และหน้าค่าสด คนดูจากระยะไกลเข้าใจทันทีว่า "แสงอยู่ทางซ้าย 12°" และใช้อธิบายกรรมการได้ ใช้เวลาทำ ~1.5 ชม. (SVG path + 1 ฟังก์ชัน)

```

     -45°  ╲  ▒▒▒│▒▒▒  ╱  +45°        ▒ = เกณฑ์ ±tol
            ╲ ▒▒▒│▒▒▒ ╱               ● = ทิศแสง θ

  -90°        ╲ ╱┆╲ ╱        +90°
```

### 4.8 ไอคอน

SVG sprite inline 1 ชุด (`<svg hidden><symbol id="i-…">`) เส้น 1.5px ขนาด 16px สี `currentColor` ประมาณ 14 ตัว: plug (เชื่อมต่อ), cpu (ฮาร์ดแวร์), rotate (ตัวขับ), target (คาลิเบรต), sun (ภารกิจ 1), camera (ภารกิจ 2), activity (ค่าสด), sliders (จูนค่า), clipboard (AI), download, terminal, alert-triangle, check, x, square (STOP) ใช้ path จาก Lucide (ISC license ใส่หมายเหตุลิขสิทธิ์ในไฟล์) หรือวาดเอง ใช้ในแถบซ้าย แถบสถานะ และป้ายสถานะเท่านั้น **ห้ามใช้ emoji** และห้ามใส่ไอคอนหน้าหัวข้อทุกหัวข้อ

### 4.9 การเคลื่อนไหว

- เปลี่ยนสถานะสี/พื้นหลัง 120 ms เท่านั้น ไม่มี slide/fade ของหน้า
- ไม่มีไฟกระพริบ ยกเว้น: กด STOP แล้วปุ่ม STOP กะพริบขอบ 1 ครั้ง (ยืนยันว่าส่งแล้ว) และป้าย "หลุด!" กะพริบช้า 2 ครั้งแล้วค้าง
- เคารพ `prefers-reduced-motion`

### 6.5 การทดสอบ

**อัตโนมัติ (ต้องผ่านทุกครั้งก่อน build)**
- `node tool/tests/run_tests.js` — ชุดนี้โหลดเฉพาะ 01, 02, 04, 05, 06, 07 (`run_tests.js:5`) การรื้อ UI จึงไม่กระทบ แต่ต้องเพิ่ม `06b_rules.js` เข้าไปในรายการ และเพิ่มการทดสอบ: เกณฑ์ Fit (ผ่าน/เตือน/ไม่ผ่านที่ขอบ 0.3°, γ 0.4/0.9), แปลรหัส ERR ทุกรหัสใน PROTOCOL.md, invalidation (ทำ AMB ใหม่ → C6–C9 ต้องทำใหม่), boresight ปฏิเสธภาพ m1 ≠ HOLD
- `node tool/build.js` ต้องไม่ error (ตรวจ `</script` อยู่แล้ว `build.js:14`) และขนาดไฟล์ควรอยู่ใต้ ~260 KB (ตอนนี้ ~195 KB)
- **smoke test ในเบราว์เซอร์โดยไม่ติดตั้งอะไร**: เพิ่มโหมด `#selftest` ใน `09_app.js` (ทำงานเฉพาะเมื่อ hash นี้) ที่ต่อตัวจำลอง → AMB (ปิดหลอดผ่าน `S.tr.world`) → SWEEP → Fit → M1 START รอผล → M2 GO แล้วเขียนผล JSON ลง `<pre id="selftest">` จากนั้น `tool/tests/ui_smoke.js` เรียก Chrome ที่มีอยู่แล้ว `chrome --headless=new --virtual-time-budget=200000 --dump-dom file:///…#selftest` แล้วตรวจ JSON (ถ้าไม่มี Chrome ให้ข้าม) วิธีนี้พิสูจน์แล้วในการทำเอกสารนี้: ตัวจำลองวิ่งครบ Sweep + Fit + M1 HOLD + ภาพ 2 ภาพ ภายใต้ virtual time ในไม่กี่วินาที

**ด้วยมือในโหมดจำลอง (ทำทั้ง 1366×768 และ 1920×1080, ธีมสว่างและมืด)**
1. เปิดไฟล์ด้วยดับเบิลคลิก (file://) ไม่ต่ออินเทอร์เน็ต: ฟอนต์ไทยไม่แตก ไอคอนขึ้นครบ ไม่มี error ใน DevTools console
2. ต่อจำลอง: แถบลายจำลองขึ้นทั้งแถบ; ตัดการเชื่อมต่อ: ป้ายเปลี่ยน
3. คลิก START แล้วกด Space → ต้องได้ `STOP` ในคอนโซล **ไม่ใช่** `M1 START` ซ้ำ; ทดสอบ Space ตอนโฟกัสปุ่มในแถบซ้าย, select, checkbox; Esc ตอนพิมพ์ในช่องกรอกคอนโซลต้อง STOP ด้วย
4. พิมพ์ `SET ctl.k 9` ในคอนโซล → ถาดปัญหาขึ้น 1 พร้อม "ค่าต้องอยู่ระหว่าง 0.1 ถึง 1.5" และยังอยู่หลังผ่านไป 1 นาที
5. `SET ctl.db 0.2` → แถบสถานะ "ยังไม่ SAVE 1" → คลิก → SAVE → หายไป
6. คาลิเบรตครบ 10 ขั้นในโหมดวันแข่ง โดยใช้แค่ปุ่มหลัก + ถัดไป: ต้องไม่ต้องเปิดคอนโซลเลย; ขั้น C4 ลองกดวัดทั้งที่หลอดยังเปิด → ต้องถูกเตือน
7. ทำ C4 ใหม่หลังจบ → C6–C9 เป็น "ต้องทำใหม่"
8. ภารกิจ 1: START → เห็นแถบคงเป้าเดิน → ผลตัดสินขึ้นเหนือกราฟโดยไม่ต้องเลื่อนจอที่ 1366×768; กด "ดันเบี้ยว 15°" ระหว่างคงเป้า → ต้องได้ "ไม่ผ่าน: หลุด HOLD"
9. ภารกิจ 2: ตั้ง offset 250 → GO → แถบ "ไม่ถ่าย" ค้าง พร้อมปุ่มทางแก้; SNAP ตอน M1 พัก → boresight ต้องไม่ยอมให้ "ใช้ค่านี้"
10. แผง AI: ใส่อาการ → คัดลอก → วางใน Notepad: มีอาการ + คำสั่งล่าสุด + ค่าต่างจากค่าเริ่ม
11. สลับธีมระหว่างที่กราฟวิ่ง: สีกราฟเปลี่ยนตาม
12. ย่อหน้าต่างเหลือ 1280×720: ไม่มีอะไรซ้อนทับ แถบสถานะตัดข้อความรองก่อน (θ กับ STOP ต้องอยู่เสมอ)
13. Replay log เก่า (แท็บหลักฐาน) ยังเล่นได้และแถบสถานะอัปเดตตาม

## 8. สิ่งที่**ไม่**ควรทำ

- ไม่เปลี่ยนเป็น framework (React/Vue/Tailwind CDN) — ผิดข้อกำหนดออฟไลน์ไฟล์เดียว และเพิ่มความเสี่ยงช่วงสุดท้าย
- ไม่ใส่ไลบรารีกราฟ (Chart.js ฯลฯ) — canvas เดิมเร็วและพอ
- ไม่ทำ gradient, glassmorphism, เงาใหญ่, animation เข้าหน้า, emoji, ไอคอนประดับทุกหัวข้อ, จุดสถานะที่ไม่มีข้อความ
- ไม่ซ่อนคอนโซลทิ้ง: ทีมทำงานกับ serial output เป็นหลัก คอนโซลต้องเปิดได้ในหนึ่งคลิกเสมอ
- ไม่เปลี่ยนชื่อคำสั่ง protocol ในหน้าจอเป็นภาษาไทยล้วน — แสดงทั้งสองอย่าง (ชื่อไทย + คำสั่งจริง)
