## 0. หลักคิดที่จะใช้ชนะ

รอบภูมิภาคทีมผ่านเพราะเตรียมโค้ดที่ดีกว่าโค้ดตัวอย่างของผู้จัด แล้วปรับให้เข้ากับฮาร์ดแวร์ผู้จัดหน้างาน รอบชิงใช้สูตรเดิมแต่ทำให้แรงขึ้น 3 ด้าน

1. **ปรับเข้ากับฮาร์ดแวร์ได้ในไม่กี่นาที**
   - แก้ค่าทุกอย่าง (ขา ชนิดมอเตอร์ ค่าจูน) ผ่านคำสั่งได้โดยไม่ต้อง upload ใหม่
   - มีคำสั่งสำรวจฮาร์ดแวร์อัตโนมัติ
   - มี Context Pack สำหรับแปะให้ AI
2. **แม่นและนิ่งกว่าทีมอื่น**
   - ใช้โมเดลฟิสิกส์ของเซนเซอร์คู่กับการคาลิเบรตที่ทนต่อความสว่างหลอดที่เปลี่ยนไป
   - ออกแบบการควบคุมโดยคำนึงว่า LDR ตอบสนองช้า
3. **มีหลักฐานและอธิบายได้:** มีกราฟ ตัวเลขความคลาดเคลื่อน log และเอกสารทฤษฎีไว้ตอบกรรมการ

## 1. สัญญากลาง: Protocol + Config (ทำก่อนทุกชิ้น)

firmware, tool และ simulator ใช้ภาษาคำสั่งเดียวกัน tool จึงสลับไปต่อบอร์ดจริงได้ทุกช่องทาง ไม่ว่าจะเป็น USB, WiFi, ผ่านสถานีภาคพื้น หรือตัวจำลอง โดยไม่ต้องแก้ tool

**รูปแบบบรรทัด:** ข้อความ ASCII จบบรรทัดด้วย `\n`
- ส่งไปบอร์ด: `[@id] คำสั่ง อาร์กิวเมนต์...` เช่น `@7 SET ctl.kp 0.6`
- บอร์ดตอบกลับ:
  - `@7 OK ...` หรือ `@7 ERR <code> <ข้อความ>`
  - `TH,<ชื่อคอลัมน์...>` ตามด้วย `T,<ค่า...>` เป็น telemetry แบบ CSV ที่บอกหัวคอลัมน์เอง firmware จึงเพิ่มค่าได้โดย tool ไม่พัง
  - `J {json}` สำหรับข้อมูลที่มีโครงสร้าง เช่น schema ของ config, รายงานฮาร์ดแวร์, ผล sweep
  - `E <event> ...` สำหรับเหตุการณ์ เช่น เปลี่ยนสถานะ หรือเกิด fault
  - `# ...` สำหรับข้อความ debug ที่คนอ่าน
  - `IMG ...` สำหรับภาพ ส่งเป็นชิ้น base64 พร้อม CRC และขอส่งซ้ำเฉพาะชิ้นที่หายได้
- ช่องทางไร้สายเติม checksum `*XXXX` (CRC-16) ท้ายบรรทัด ช่องทาง USB ไม่ต้องใส่

**Config registry**
- ค่าทุกตัวลงทะเบียนในบอร์ดที่เดียว มีชื่อ ชนิด ค่าเริ่มต้น min/max หน่วย กลุ่ม และคำอธิบายภาษาไทย เก็บใน NVS ผ่าน `Preferences`
- `CFG LIST` ส่ง schema เป็น JSON แล้ว tool จะสร้างหน้าตั้งค่าและสไลเดอร์ให้เอง เพิ่มค่าใหม่ใน firmware ก็โผล่ใน tool ทันที
- มี `SET / GET / SAVE / LOAD / DEFAULTS / EXPORT / IMPORT` และเซฟโปรไฟล์ทั้งชุดเป็นไฟล์ JSON ในคอมได้
- ตั้งชื่อค่าตามกลุ่ม: `sen.*` เซนเซอร์, `est.*` การคำนวณมุม, `act.*` ตัวขับ, `ctl.*` การควบคุม, `m1.*`, `m2.*`, `cam.*`, `com.*`

เอกสารของส่วนนี้: `firmware/PROTOCOL.md` มีสเปกเต็มและตัวอย่างของทุกคำสั่ง

### 2.3 สายสัญญาณเซนเซอร์ (sensors + sunest)
ลำดับการประมวลผลในแต่ละรอบ
1. อ่านด้วย `analogReadMilliVolts()` ซึ่งใช้ค่าคาลิเบรตจากโรงงานของ ESP32-S3 อ่านสลับลำดับ L, R, R, L ให้เวลาเฉลี่ยของสองฝั่งตรงกัน
2. เฉลี่ยในหน้าต่าง 20 ms เพื่อตัดไฟกระพริบ 100 Hz จากไฟบ้าน 50 Hz แล้วใช้ median ตัด spike
3. แปลงแรงดันเป็นความต้านทาน LDR ตามทิศของวงจร (LDR อยู่ฝั่งบนหรือล่าง ตั้งค่าได้) แล้วหา conductance G = 1/R
4. แปลงเป็นความสว่างสัมพัทธ์ E = G^(1/γ) แล้วลบแสงรอบข้าง (ambient) ที่วัดไว้ตอนปิดหลอด
5. ปรับ gain ให้สองฝั่งเท่ากัน แล้วคิด D = (E_L − E_R)/(E_L + E_R) และ S = E_L + E_R
6. หามุมจากโมเดล θ = atan(D / tan α) − θ0 แล้วแก้ความคลาดเคลื่อนที่เหลือด้วย LUT จากการ sweep
7. ตรวจความถูกต้อง แล้วตั้งธงสถานะใน telemetry
   - S ต่ำ = ไม่เห็นแสง
   - แรงดันชิดขอบ = saturate
   - ค่ากระโดดผิดปกติ = fault

**ทำไมข้อ 3–4 สำคัญที่สุด:** ค่า ADC ดิบจากวงจรแบ่งแรงดันไม่แปรตามความสว่างเป็นเส้นตรง กราฟ D–มุมจึงเปลี่ยนเมื่อหลอดสว่างขึ้นหรือย้ายไปไกลขึ้น ถ้าคำนวณบน conductance หรือความสว่างแทน ความสว่างของหลอดจะหักล้างกันจริง ค่าที่คาลิเบรตไว้ตอนซ้อมจึงยังใช้ได้แม้ไฟห้องแข่งจะต่างไป

รองรับทั้งเซนเซอร์ 2 ตัว (1 แกน) และ 4 ตัว (2 แกน) จับคู่แกนได้จาก config

| **Stepper 28BYJ-48 + ULN2003 (P0 ตัวหลัก)** | นับ step แปลงเป็นมุม (half-step ละเอียดราว 0.088°) | ดูรายละเอียดด้านล่าง |
| Servo (P0) | สั่งมุมตรงเป็น µs ละเอียดต่ำกว่า 1° | ใช้ LEDC 50 Hz ความละเอียดสูง จำกัดช่วงมุมและความเร็ว |
| DC motor + เกียร์ (P1) | PWM + ทิศ ใช้ PID บนมุม | ชดเชย PWM ขั้นต่ำที่มอเตอร์เริ่มหมุน และสั่งเบรกได้ |
| Reaction wheel บนฐานหมุนอิสระ (P1) | คุมแรงบิดด้วยการเร่งหรือลดล้อ ใช้ PD ร่วมกับไจโร | จำกัดความเร็วล้อ และต้องมี IMU/gyro |

**รายละเอียดตัวขับ stepper (ULN2003)**
- เขียนตัวขับเองแบบไม่ block ใช้ timer เดิน step ไม่ใช้ `Stepper.h`
  - ขา IN1–IN4 และลำดับขดลวดตั้งได้จาก config
  - มี sequence ให้เลือก 3 แบบ: wave, full-step, half-step
  - `Stepper.h` เดินแบบ block และมีปัญหาลำดับขาที่คนพลาดกันบ่อย
- มี ramp เร่งและลดความเร็ว และจำกัดความเร็วสูงสุดได้ เพราะถ้าเร็วเกินไป stepper จะหลุด step
- ใช้ค่า step ต่อรอบจาก config แล้วคาลิเบรตได้ด้วยคำสั่ง `SPR`
- ชดเชย backlash ตอนกลับทิศ ค่าวัดอัตโนมัติด้วยคำสั่ง `BACKLASH` และเข้าเป้าจากทิศเดิมเสมอ
- ปิดไฟขดลวดตอนหยุดนิ่งได้ (ตั้งค่าได้) เพื่อลดความร้อนและ noise เฟืองมีแรงเสียดทานพอจะค้างตำแหน่งไว้
- วัดแสงเฉพาะช่วงที่มอเตอร์หยุดนิ่ง (quiet window) กันกระแสมอเตอร์กวนค่า ADC
- ไม่มี encoder บอกมุมจริง จึงต้องตั้งศูนย์ด้วยวิธีใดวิธีหนึ่ง
  - ใช้ sun sensor เป็นจุดอ้างอิง
  - หรือใช้ขีดบอกตำแหน่งแล้วสั่ง `ZERO`
- มี soft limit จำกัดมุมรวม กันสาย USB พันเมื่อหมุนหลายรอบ

### 2.5 ภารกิจ 1: Sun Tracking (mission1)
state machine: `IDLE → SEARCH → SLEW → FINE → HOLD` และมี `LOST`, `FAULT`
- **SEARCH:** ถ้า S ต่ำ (ไม่เห็นแสง) ให้หมุนกวาดทั้งช่วง บันทึก S และ D แล้วหาจุดที่แสงแรงสุดหรือจุดที่ D ตัดศูนย์
- **SLEW:** พอเห็นแสงแล้ว คำนวณมุมที่ต้องไปครั้งเดียว (มุมปัจจุบัน + θ) แล้วหมุนไปโดยจำกัดความเร็ว
- **FINE:** วนรอบ "ขยับ → รอ → วัด" ขยับแก้ k·θ แล้วรอให้ตัวขับนิ่งและ LDR ตามทัน (ประมาณ 3τ) ค่อยวัดใหม่ จะได้ไม่แกว่งเพราะ LDR ช้า ถ้าเป็น stepper ช่วงวัดคือตอนที่มอเตอร์หยุดแล้วเท่านั้น
- **HOLD:** ถ้าอยู่ใน deadband ติดกัน N ครั้งถือว่าล็อก และจะขยับอีกเมื่อ error เกิน threshold ที่ใหญ่กว่า (hysteresis) จึงไม่ส่าย
- เข้าเป้าจากทิศเดิมทุกครั้ง (anti-backlash) จึงหยุดตรงจุดเดิมซ้ำได้
- รองรับคำสั่งแบบ "หันทำมุม X กับแสง" เผื่อกรรมการกำหนดมุมอื่น
- รายงานมุมแสง, pointing error, เวลาที่ใช้เข้าเป้า และสถานะ ใช้เป็นหลักฐานได้
- พารามิเตอร์ภารกิจทั้งหมด (มุมเป้า, tolerance, dwell) ตั้งผ่าน `SET` ได้ รู้เงื่อนไขตอน 08:30 ก็ตั้งค่าได้ทันทีโดยไม่ต้องแก้โค้ด

### 2.6 ภารกิจ 2: Target Imaging (camera + mission2)
- ตั้งขากล้องจาก preset (ESP32-S3-EYE / XIAO / Freenove / custom) หรือคัดลอกขาจากโค้ดผู้จัดมาใส่
- **ถ้ากล้องอยู่คนละบอร์ด (P1):** เช่น บอร์ด ESP32-S3 กล้องแยกจาก SunSeek มี sketch `CamNode` ให้บอร์ดกล้องรับคำสั่งถ่ายจากบอร์ดหลักทาง UART หรือ ESP-NOW แล้วส่งภาพกลับ ใช้ protocol เดียวกัน
- **ปล่อยให้ auto ปรับแสงก่อนแล้วล็อก:** เปิด auto 1–2 วินาทีให้ภาพสว่างพอดี แล้วปิด AEC/AGC/AWB ทุกภาพจะได้แสงเท่ากัน (ต้องทดสอบกับกล้องรุ่นจริงว่าค่าที่ล็อกคงอยู่)
- **ล้างเฟรมค้าง:** ทิ้ง 1–2 เฟรมแรกก่อนถ่ายจริง กันได้ภาพจากตอนที่ยังหมุนไม่เสร็จ
- **เงื่อนไขถ่าย:** นิ่งครบ dwell time, pointing error ต่ำกว่าเกณฑ์ และล็อกแสงแล้ว จึงถ่าย
- **ตรวจไฟล์ JPEG:** เช็กขนาด หัวไฟล์ FFD8 และท้ายไฟล์ FFD9 ถ้าไม่ผ่านให้ถ่ายใหม่อัตโนมัติ
- **ช่องทางส่งภาพ:** USB เป็นชิ้น base64 + CRC (P0), HTTP จากบอร์ดผ่าน WiFi (P1), ESP-NOW ผ่านสถานีภาคพื้น (P1)
- **metadata ของแต่ละภาพ:** เวลา มุม error สถานะ และค่ากล้อง เก็บไว้เป็นหลักฐานให้กรรมการ
- **(P1) Boresight:** ถ่ายหลอดไฟตอนที่เซนเซอร์บอกว่าตรง แล้วหาจุดสว่างในภาพ จะรู้ว่ากล้องเยื้องกับเซนเซอร์กี่องศาแล้วชดเชยได้
- **(P1) หาเป้าในภาพ:** หาจุดสีหรือจุดสว่าง แล้วหมุนจนเป้าอยู่กลางภาพ (visual servoing) ใช้เมื่อเป้าเห็นชัด

### 2.7 คำสั่งช่วยหน้างาน (diag)

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `HWID` | รายงานชิป, PSRAM, flash, เวอร์ชัน core, สาเหตุรีเซ็ต และอุปกรณ์ I2C ที่เจอ (IMU, INA219, กล้อง) |
| `PINFIND` | แสดงแรงดันของทุกขา ADC แบบสด เอามือบัง LDR แล้วดูว่าขาไหนขยับ โดยเว้นขา USB 19/20 และขากล้องที่ตั้งไว้ |
| `DARK` / `AMB` | เก็บค่าแสงรอบข้างตอนปิดหลอด |
| `BAL` | ชี้ตรงหลอดแล้วเก็บอัตราส่วน gain ให้สองฝั่งเท่ากัน |
| `SWEEP a b step dwell` | หมุนเองทีละขั้น เก็บค่าเซนเซอร์ทุกจุด แล้วส่งตารางให้ tool นำไป fit |

| `BACKLASH` | วัด backlash ของเฟืองอัตโนมัติ โดยกวาดไปและกลับ แล้วเทียบจุดที่ D ตัดศูนย์ |
| `ZERO` | ตั้งตำแหน่งปัจจุบันเป็นมุม 0 |
| `SELFTEST` | ตรวจทุกระบบย่อย ตอบ PASS/FAIL รายข้อ |
| `DIAG` | สรุปสถานะราว 10 บรรทัด ไว้แปะให้ AI |
| `STOP` | หยุดทุกอย่างทันที (ใน tool กด Space) |

### 2.8 ความปลอดภัยและความทนทาน

- เกิด fault เมื่อไรให้เข้า SAFE หยุดตัวขับแต่ยังสื่อสารได้

### 3.4 คณิตศาสตร์การ fit ในเบราว์เซอร์
- **โมเดลฟิสิกส์:** E_i = K·f(θ − θ_i) + A โดย f = cos ที่ถูกตัดตามขอบ FOV ของกล่อง แล้ว fit α_eff, γ, gain ratio, ambient A และ θ0 ด้วย Levenberg–Marquardt
- **LUT:** แก้ความคลาดเคลื่อนที่เหลือ (residual) ด้วยการ interpolate เชิงเส้น
- **ตัววัดผล:** MAE, max error, RMS, ความซ้ำ (repeatability) และ hysteresis จากการกวาดไป-กลับ
- **เทียบโมเดล:** raw-ADC แบบเส้นตรง, atan(D)·k, physics และ physics + LUT เพื่อแสดงให้เห็นว่าทำไมของเราดีกว่า ใช้ตอบกรรมการได้

### 3.5 ตัวจำลอง (Simulator)
- **ฟิสิกส์ที่จำลอง:**
  - หลอดไฟ: มุม, ความสว่าง, ไฟกระพริบ 100 Hz และแสงรอบข้าง
  - LDR คู่: α, γ, ค่าที่ไม่เท่ากัน, noise, การหน่วง 20–30 ms และขอบ FOV ของกล่อง
  - วงจรแบ่งแรงดันและ ADC 12 บิต
  - ตัวขับ: stepper 28BYJ-48 ที่มี step ละเอียด ความเร็วจำกัด หลุด step เมื่อเร่งเกิน และมี backlash, servo ที่มี deadband และความเร็วจำกัด, DC motor ที่มีแรงเสียดทาน และ reaction wheel
- **จำลอง firmware ด้วย JS:** ตอบคำสั่งชุดเดียวกัน เช่น CFG, DARK, BAL, SWEEP, STEP, M1 และ M2 SNAP ที่ให้ภาพจำลองมีเป้า
- **สถานการณ์ซ้อม:** หลอดย้าย, หลอดหรี่, เปิดไฟห้อง, เซนเซอร์ไม่เท่ากัน, servo มี backlash แล้วให้คะแนนจากเวลาเข้าเป้าและ error สุดท้าย

  - Tune ที่สร้างเองจาก CFG LIST
  - Mission 1, Mission 2 (ถ่ายและดูภาพ)
  - Export, ปุ่มคัดลอกให้ AI
  - Simulator พื้นฐาน (stepper + servo)

## 4. ชิ้นที่ ③ เอกสารทฤษฎี + คู่มือหน้างาน

### 4.1 เป้าหมาย
1. ทีมเข้าใจทุกสูตรจนอธิบายเองได้
2. ใช้นำเสนอและตอบคำถามกรรมการ
3. มีคู่มือหน้างานที่ทำตามได้แม้อยู่ภายใต้ความกดดัน

รูปแบบเป็น Markdown ภาษาไทย พร้อมไฟล์ HTML ที่พิมพ์ได้ และกราฟที่สร้างจากสคริปต์ Python เพื่อให้ตัวเลขตรวจสอบได้

### 4.2 เนื้อหา
1. ภาพรวมระบบเทียบกับดาวเทียมจริง (ADCS / OBC / EPS / COMM / Payload และลูป sensor → estimator → controller → actuator)
2. Sun sensor แบบตัว V ของทีม
   - กฎโคไซน์และการพิสูจน์ D = tanθ·tanα
   - การเลือก α ซึ่งต้องแลกระหว่างความไวกับช่วงวัด
   - ผลของกล่องครอบที่มีต่อ FOV
3. LDR และวงจร
   - กฎ R ∝ E^(−γ) และวงจรแบ่งแรงดัน
   - เลือกค่าตัวต้านทานให้ไวที่สุด
   - ADC ของ ESP32-S3
   - เหตุผลที่ต้องแปลงเป็น conductance และวิธีตัดไฟกระพริบ
4. การคาลิเบรต: ขั้นตอน, โมเดล + LUT, การวัดผล และการเทียบวิธีต่าง ๆ
5. งบความคลาดเคลื่อน (error budget)
   - noise ทำให้มุมคลาดเท่าไร
   - เซนเซอร์ไม่เท่ากันทำให้เกิด bias
   - ความละเอียดของ ADC และ servo
   - backlash และการหน่วงเวลา
6. การควบคุม
   - โมเดลของตัวขับแต่ละแบบ
   - วงจร ขยับ → รอ → วัด
   - PID และ anti-windup, deadband + hysteresis
   - การจูนจาก step response
7. ภารกิจถ่ายภาพ
   - FOV และพิกเซล, สมการภาพเบลอ, settle time
   - การล็อกแสง, boresight
   - เงื่อนไขทริกเกอร์ และการตรวจสอบภาพ
8. OBC / FDIR / COMM / EPS แบบย่อ: state machine, protocol + CRC, งบพลังงาน และ brownout
9. เชื่อมกับของจริง: coarse sun sensor บนดาวเทียมจริง และดาวเทียมไทย (ตรวจสอบข้อมูลก่อนใส่)
10. ผลการทดสอบ (เติมจากข้อมูลจริงของทีม)
11. คำถามที่กรรมการน่าจะถามพร้อมคำตอบ และโครงสไลด์นำเสนอ 5–7 หน้า
12. คู่มือหน้างาน
    - แผนรายวัน 5–9 ต.ค. ว่าวันไหนทำอะไร โดยเฉพาะบ่ายวันที่ 8 ต.ค. และ 08:30–12:00 วันที่ 9 ต.ค.
    - แผน 3 ชั่วโมงในวันแข่งแบบนาทีต่อนาที และ checklist ก่อนรันภารกิจ
    - ผังแก้ปัญหา เช่น เซนเซอร์ไม่ขยับ, servo สั่น, บอร์ดรีเซ็ต, กล้องไม่ขึ้น, พอร์ตหาย
    - ลูป "วัด → แปะให้ AI → แก้ config → ทดสอบ" ให้จบภายใน 10 นาที
    - แผนสำรองถ้าไม่มีเน็ต: tethering จากมือถือ และ checklist ที่ทำได้โดยไม่พึ่ง AI
    - cheat sheet 1 หน้าสำหรับพิมพ์ติดตัว

## 7. สิ่งที่อยากได้จากทีม (ช่วยให้แผนแม่นขึ้นมาก)
1. **โค้ดรอบภูมิภาค (.ino) และโค้ดที่กรรมการแจก** ถ้ายังมีอยู่ ใส่ไว้ในโฟลเดอร์ `ref/regional/` ข้อนี้สำคัญที่สุด เพราะในโค้ดจะมีเลขขา LDR และขา ULN2003 ของ SunSeek v1.3
2. รูปบอร์ด SunSeek v1.3 ทั้งด้านหน้าและหลัง (ถ้ามี) และวงจร LDR ว่าอยู่ฝั่ง 3.3V หรือ GND ใช้ตัวต้านทานค่าเท่าไร และ LDR เอียงกี่องศา
3. เวอร์ชัน ESP32 core ที่ใช้ตอนนั้น ดูได้จาก Boards Manager
4. เครื่องที่ใช้แข่งเป็น Windows หรือ Mac, มี Chrome/Edge ไหม และติดตั้ง Arduino IDE + core ไว้หรือยัง
5. อนุญาตไหมให้ใช้ arduino-cli แบบ portable ในโฟลเดอร์ชั่วคราวเพื่อ compile ตรวจ แล้วลบทิ้งหลังใช้
6. ทีมซื้อชุดซ้อมตามข้อ 7.1 ได้ไหม

### 7.1 ชุดซ้อมที่แนะนำ (ราคาถูก หาได้ตามร้านอิเล็กทรอนิกส์หรือร้านออนไลน์)
ใช้ทดสอบ firmware และ tool กับของจริงก่อนวันที่ 5 ต.ค. เพราะ SunSeek เป็นของ มทม. ที่แจกหน้างาน
- บอร์ด ESP32-S3 DevKitC-1 (ชิป ESP32-S3-WROOM-1 แบบเดียวกับ SunSeek) รุ่นที่มี PSRAM เช่น N16R8
- stepper 28BYJ-48 + บอร์ด ULN2003
- LDR 2–4 ตัว (เช่น GL5528) + ตัวต้านทาน 10 kΩ + breadboard + สายไฟ
- โคมไฟหรือไฟฉาย LED สำหรับจำลองดวงอาทิตย์
- (ถ้าได้) บอร์ด ESP32-S3 ที่มีกล้อง OV2640 เพื่อซ้อมภารกิจ 2
- ไม้โปรแทรกเตอร์ หรือกระดาษพิมพ์สเกลองศา สำหรับทำจิ๊กวัดมุม
