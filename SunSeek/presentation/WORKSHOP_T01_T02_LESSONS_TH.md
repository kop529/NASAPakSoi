## 3. ปัญหาที่เจอ → สาเหตุ → การแก้ → สิ่งที่ได้เรียนรู้
(แต่ละข้อทำเป็น 1 สไลด์ได้)

### ปัญหา 1: ล้อไม่หมุน หรือต้องสั่งถึง 50 % ถึงจะหมุน
- **อาการ:** สคริปต์ไล่ค่า 10 → 40 % แล้วล้อไม่หมุน ต้องสั่ง RW,50 ถึงจะหมุน บางครั้งหมุนได้แป๊บเดียวแล้วหยุด
- **สิ่งที่สงสัยตามลำดับ:**
  1. น็อตเยอะเกินไปทำให้ล้อหนัก
  2. โค้ดผิด เพราะพิมพ์ในแชตแล้วหมุน แต่รันสคริปต์แล้วไม่หมุน
- **วิธีพิสูจน์:** ส่งคำสั่งชุดเดียวกับที่สคริปต์ส่งทีละคำสั่ง ผลออกมาเหมือนกัน แปลว่าโค้ดไม่ผิด
- **สาเหตุจริง:** ไฟที่ป้อนมอเตอร์ไม่พอ
- **การแก้:** แก้แหล่งจ่ายไฟของมอเตอร์ หลังแก้ Min Start ลดจาก ~50 % เหลือ **10 %**
- **บทเรียน:**
  - เปลี่ยนตัวแปรทีละอย่าง แล้วทดสอบซ้ำด้วยคำสั่งชุดเดิม
  - ตรวจไฟเลี้ยงก่อนโทษโค้ด
  - ค่าที่วัดตอนไฟไม่พอ (~50 %) ใช้ไม่ได้ ต้องวัดใหม่ทั้งหมด

### ปัญหา 2: ทิศหมุนในใบ T01 ไม่ตรงกับตอนประกอบดาวเทียม
- **อาการ:** ใบ T01 จดว่า + = ทวนเข็ม แต่พอประกอบเป็นดาวเทียมแล้ว + = ตามเข็ม (มองจากด้านบน)
- **สาเหตุ:** ตอนวัด T01 มองล้อจากคนละด้าน
- **การแก้:** แก้ใบบันทึก และกำหนด convention ให้ชัดว่า "มองจากด้านบน ตอนประกอบแล้ว"
- **บทเรียน:** คำว่าตามเข็ม/ทวนเข็มไม่มีความหมายถ้าไม่บอกว่ามองจากด้านไหน ทิศผิดหนึ่งตัวทำให้ระบบควบคุมหมุนหนีเป้า (positive feedback) ได้

### ปัญหา 3: เฟิร์มแวร์ผู้จัดไม่รู้จักคำสั่ง `RW_CMD` (Assist)
- **อาการ:** ใบงาน T02 ให้ใช้ `RW_CMD,delta,assist,duration` แต่เฟิร์มแวร์ v2.1 ไม่ได้ส่งคำสั่งนี้ต่อ (route) ไปที่ฟังก์ชันใดเลย ทั้งที่มีฟังก์ชัน `rwMomentumCommand()` อยู่แล้ว
- **การแก้:** เพิ่ม handler 1 บรรทัดใน `System_CommandRouter.h` ให้เรียกฟังก์ชันเดิม
  - ตรวจว่าอยู่ใน MOMENTUM mode และตรวจรูปแบบคำสั่งกับช่วงค่า (duration 0–5000 ms)
  - ตอบกลับ `ACK,RW_CMD,...` ตามรูปแบบเดิม
  - ไม่แก้รูปแบบข้อความเดิม Ground Station จึงยังใช้ได้
- **ผล:** `RW_CMD,+20,+80,300` → ACK + `EVT,RW_MANEUVER_COMPLETE,60` ทั้งทาง USB และ BLE
- **บทเรียน:** อ่านโค้ดจริงเมื่อเอกสารกับเฟิร์มแวร์ไม่ตรงกัน และแก้ให้น้อยที่สุดโดยไม่ทำให้ระบบอื่นพัง

### ปัญหา 4: สั่ง ±10 % แล้วตัวดาวเทียมไม่ขยับ
- **อาการ:** ใน momentum mode ปรับทีละ ±10 % ล้อเปลี่ยนความเร็ว แต่ตัวดาวเทียมไม่หมุน
- **สาเหตุ:**
  - แรงบิดที่ล้อส่งให้ตัวดาวเทียมเกิดเฉพาะตอนความเร็วล้อเปลี่ยน (τ = −dH_wheel/dt)
  - การเปลี่ยนทีละน้อยให้แรงบิดน้อยเกินกว่าจะชนะแรงเสียดทานสถิต (stiction) ของแท่นหมุน
- **การแก้:** ใช้ Assist คือเตะแรง ๆ สั้น ๆ (80 % นาน 300 ms) แล้วกลับมาที่ bias ตัวดาวเทียมจึงหมุนได้
- **บทเรียน:** ปัญหานี้คือเหตุผลที่ต้องมีโหมด Assist และต้องชดเชย deadzone ตอนเขียนตัวควบคุมจริง (งาน F4)

### ปัญหา 5: หลัง STOP ตัวดาวเทียมหมุนย้อนกลับเล็กน้อย
- **อาการ:** สั่ง RW,30 ตัวดาวเทียมหมุนตามทิศหนึ่ง พอ STOP กลับหมุนย้อนนิดหนึ่ง
- **สาเหตุ:**
  - STOP ของเฟิร์มแวร์ผู้จัดเป็นแบบ coast (IN1 = IN2 = LOW) ไม่ใช่เบรก
  - ตอนล้อค่อย ๆ ช้าลง แรงเสียดทานในมอเตอร์คืนโมเมนตัมเชิงมุมให้ตัวดาวเทียม ตัวดาวเทียมจึงหมุนกลับ
- **บทเรียน:**
  - โมเมนตัมเชิงมุมของทั้งระบบอนุรักษ์ เวลาเร่งหรือหยุดล้อจะมีผลกับตัวดาวเทียมเสมอ
  - ตัวควบคุมต้องรับมือช่วงล้อหยุดด้วย

### ปัญหา 6: เปลี่ยนเป็น `ADCS_STRATEGY,MOMENTUM` แล้วเหมือนไม่มีอะไรเกิดขึ้น
- **สาเหตุ:** คำสั่งนี้แค่เปลี่ยนกลยุทธ์ ยังไม่ได้สั่ง bias ต้องสั่ง `RW_BIAS,n` ก่อน
- **สิ่งที่เห็นเมื่อสั่ง bias:** ล้อหมุนค้าง แต่ตัวดาวเทียมนิ่ง เท่ากับเก็บโมเมนตัมไว้ในล้อ (momentum bias) ช่วยให้ระบบแข็ง (gyroscopic stiffness) และควบคุมได้ทั้งสองทิศจากจุดกลาง
- **บทเรียน:** เข้าใจความต่างระหว่าง Reaction กับ Momentum
  - Reaction: ล้อเริ่มจาก 0 แล้วหมุนสวนทางกับตัวดาวเทียม
  - Momentum: ล้อหมุนรอที่ bias แล้วปรับขึ้นลงรอบค่านั้น

### ปัญหา 7: Ground Station หาบอร์ดไม่เจอ (Found 0 device)
- **อาการ:** เชื่อมไม่ได้ ปุ่ม TT&C ใช้ไม่ได้ สแกนไม่เจออุปกรณ์
- **สาเหตุ:**
  - บอร์ดไม่มีไฟหรือสายหลุด
  - บอร์ดยังค้างสถานะ `BLE,CONNECTED` ของการเชื่อมเก่า
  - BLE รับได้ทีละ 1 การเชื่อม และหยุดประกาศตัว (advertise) ระหว่างที่มีการเชื่อมอยู่
- **การแก้:** กด RESET ที่บอร์ด → ปิดแล้วเปิด GS ใหม่ → สแกนใหม่
- **ระวัง:** มีบอร์ดทีมอื่นอยู่ใกล้ ๆ ต้องเช็ก MAC ของเรา `44:1B:F6:77:FF:99` ก่อนกด connect เสมอ
- **บทเรียน:**
  - เตรียมขั้นตอนกู้คืนการเชื่อมต่อไว้ก่อนวันแข่ง
  - BLE หลุดแล้วล้อไม่หยุดเอง ต้องมีวิธีสั่ง STOP สำรองทาง USB

### ปัญหา 8: ปัญหาในสคริปต์ทดสอบของทีม (`t01.ps1`)
| อาการ | สาเหตุ | การแก้ |
|---|---|---|
| Windows ไม่ยอมรันสคริปต์ | Execution Policy | รันด้วย `-ExecutionPolicy Bypass` เฉพาะครั้งนั้น (ไม่ปิด Smart App Control) |

| ภาษาไทยในสคริปต์เพี้ยน | PowerShell 5.1 ต้องการไฟล์ UTF-8 แบบมี BOM | บันทึกไฟล์ใหม่เป็น UTF-8 BOM |
| จด Min Stable = 40 % ทั้งที่ล้อไม่เคยหมุน | ตรรกะไม่ได้ตรวจว่าล้อเริ่มหมุนแล้วหรือยัง | ถ้าไม่เคยหมุนให้ข้ามและจด "วัดไม่ได้" |

- **บทเรียน:**
  - เครื่องมืออัตโนมัติช่วยให้วัดซ้ำได้เหมือนเดิมทุกครั้ง แต่ต้องทดสอบตัวเครื่องมือเองด้วย
  - สคริปต์สั่ง STOP เสมอตอนจบหรือตอนกด Ctrl+C (ใช้บล็อก `finally`) เพื่อความปลอดภัย

## 4. ปัญหาที่ยังเปิดอยู่ (สไลด์ "งานต่อไป")
- **IMU ขึ้น NOT_DETECTED** ทั้ง accel, mag, gyro และ baro มีแต่ sun sensor ที่ READY ต้องตรวจ GY-89 (I2C ที่ io8/io9) ก่อนทำ sun tracking
- เอาคำสั่ง `RW_CMD` ไปใส่ในเฟิร์มแวร์ของทีม
- F4 ชดเชย deadzone ของล้อ (ใช้ Min Start 10 % / Min Stable 5 % จาก T01) เพื่อไม่ให้ตัวควบคุมหยุดก่อนถึงเป้า

## 5. สิ่งที่ทีมได้เรียนรู้ (สไลด์สรุป)
1. **ฟิสิกส์:**
   - แรงบิดเกิดจากการเปลี่ยนความเร็วล้อ ไม่ใช่จากความเร็วล้อ
   - โมเมนตัมเชิงมุมของทั้งระบบอนุรักษ์
   - แรงเสียดทานสถิตกำหนดค่าคำสั่งขั้นต่ำ
2. **วิศวกรรม:** วัดคุณลักษณะของแอกชูเอเตอร์ก่อน (deadzone, ช่วงเชิงเส้น, สมมาตร) แล้วค่อยออกแบบตัวควบคุม
3. **การแก้ปัญหา:** ตั้งสมมติฐาน แล้วทดสอบทีละตัวแปร (น้ำหนัก → โค้ด → ไฟ)
4. **Convention:** ต้องระบุทิศและมุมมองให้ชัดตั้งแต่แรก
5. **ซอฟต์แวร์:** แก้เฟิร์มแวร์ให้น้อยที่สุด และคงรูปแบบข้อความเดิมไว้ให้ Ground Station
6. **ปฏิบัติการ:**
   - มีขั้นตอนกู้การเชื่อมต่อ BLE
   - เช็ก MAC ก่อนเชื่อม
   - มีทางสั่ง STOP สำรอง
