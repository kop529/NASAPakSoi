# สิ่งที่ทีมแก้ในโค้ดของกรรมการ และทำไมของเราดีกว่า
ทีม **นาซ่าหน้าปากซอย (NasaPakSoi)** · เฟิร์มแวร์ผู้จัด SunSeek v2.1 → เฟิร์มแวร์ทีม `NasaPakSoi-team-1`

> ใช้ทำสไลด์ "สิ่งที่เราพัฒนาเพิ่ม" · ตัวเลขในหัวข้อ "หลักฐาน" ได้จากการจำลองทั้งระบบ (host test) ยกเว้นข้อที่เขียนว่าวัดบนบอร์ดจริง

## หลักการ 4 ข้อ (สไลด์แรก)
1. **ไม่ทำลายของเดิม:** รูปแบบข้อความ TM / ACK เหมือนเดิมทุกตัว ทำให้ Ground Station ของกรรมการยังใช้ได้ ส่วนคำสั่งใหม่ขึ้นต้นด้วย `TEAM_` ทั้งหมด
2. **ค่าเริ่มต้นเท่ากับของกรรมการ:** ถ้า flash ยังว่าง บอร์ดจะทำงานเหมือนเฟิร์มแวร์ผู้จัดทุกอย่าง ถ้ามีปัญหาก็ถอยกลับได้ทันที
3. **ทุกจุดที่แก้มีป้าย `TEAM NasaPakSoi`:** กรรมการตรวจได้ว่าแก้อะไรไปบ้าง
4. **เก็บเฟิร์มแวร์ไว้ 2 ชุด:**
   - ชุด workshop: เหมือนของกรรมการ แก้แค่ชื่อทีมกับเพิ่ม `RW_CMD` ใช้ตอนครูตรวจ
   - ชุด team: ใช้แข่ง

## รายละเอียดทีละข้อ (สไลด์ละข้อ)

### 1. `RW_CMD` ใช้ไม่ได้ในเฟิร์มแวร์ผู้จัด
- **ปัญหา:** ใบงาน T02 สั่ง `RW_CMD,delta,assist,duration` แต่ router ของ v2.1 ไม่ส่งคำสั่งนี้ไปไหนเลย ทั้งที่มีฟังก์ชัน `rwMomentumCommand()` อยู่แล้ว
- **ที่เราทำ:**
  - เพิ่ม handler ที่ตรวจว่าอยู่ใน MOMENTUM mode ตรวจรูปแบบคำสั่ง และตรวจช่วงค่า (0–5000 ms)
  - ตอบ `ACK,RW_CMD,...` หรือ `ERR,...` ตามรูปแบบของกรรมการ
- **หลักฐาน (บอร์ดจริง):** `RW_CMD,+20,+80,300` → `EVT,RW_MANEUVER_COMPLETE,60` ทั้งทาง USB และ BLE ครูตรวจผ่าน

### 2. อ่าน sun sensor แบบเฉลี่ย
- **ปัญหาของการอ่านครั้งเดียว:**
  - ADC ของ ESP32 มีสัญญาณรบกวนสูง
  - หลอดไฟบ้าน (ไฟ 50 Hz) สว่างกะพริบ 100 ครั้งต่อวินาที การอ่านครั้งเดียวจะได้ค่าสูงหรือต่ำแล้วแต่จังหวะ
- **ที่เราทำ:**
  - งานเบื้องหลัง (FreeRTOS task) อ่านทุก 2 ms แล้วเฉลี่ยในหน้าต่าง 20 ms
  - 20 ms = 2 รอบของการกะพริบพอดี การกะพริบจึงหักล้างกันเอง
- **หลักฐาน (จำลอง):** ใส่ไฟกะพริบ 30 % มุมคลาดเพิ่มแค่ 0.007°

### 3. โมเดลคำนวณมุมดวงอาทิตย์
- **ปัญหาของ 90 × NDV:**
  - LDR ไม่เป็นเชิงเส้น ความต้านทานแปรตามแสงยกกำลัง γ
  - วงจรแบ่งแรงดันเพิ่มความไม่เชิงเส้นอีกชั้น
  - มีแสงรอบข้าง (ambient) ปนเข้ามา
  - NDV จึงไม่ได้เป็นเส้นตรงกับมุม และเปลี่ยนตามความสว่างหรือระยะของหลอด
- **ที่เราทำ (มาจากโครงการ NasaSat ของทีม):**
  1. แรงดัน → conductance G = V / (Vcc − V) ซึ่งแปรตาม (แสง)^γ
  2. ยกกำลัง 1/γ ให้กลับเป็นปริมาณแสง แล้วหักแสงรอบข้าง
  3. ปรับ gain ของซ้ายและขวาให้เท่ากัน แล้วหาค่า D = (L − R) / (L + R)
  4. เรขาคณิตของเซนเซอร์สองตัวที่เอียงทำมุม α: θ = atan(D / tan α) + th0
  5. ใช้ LUT แก้ความคลาดเคลื่อนที่ยังเหลือ
- **หลักฐาน (จำลอง):** มุมจริง 20.00° → ของเราได้ 20.001° · ของกรรมการได้ 3.30°
- **ความปลอดภัย:** ค่าเริ่มต้นคือ `sun.model 0` = สูตรของกรรมการ จะเปลี่ยนเป็นโมเดลของเรา (`sun.model 1`) หลัง calibrate กับแท่นจริงแล้วเท่านั้น

### 4. ตรวจจับแสงเสีย
- ADC ชนเพดาน (แสงจ้าเกิน), แสงน้อยเกินไป หรือแสงเข้ามาจากมุมขอบ ทำให้มุมที่คำนวณได้ไม่มีความหมาย
- เราตั้งธง `sat` / `light` / `edge` ไว้ให้ตัวควบคุมใช้ตัดสินใจ งานต่อไปคือ F7 ค้นหาดวงอาทิตย์เมื่อไม่มีแสง แทนที่จะไล่ตามสัญญาณรบกวน

### 5. พารามิเตอร์ปรับได้ขณะรันและเก็บลง flash
- **คำสั่ง:** `TEAM_SET,adcs.kp,2.5` → `TEAM_SAVE` · `TEAM_LIST` · `TEAM_DEFAULTS,YES`
- **เหตุผล:**
  - วันแข่งไม่มีเวลาอัปเฟิร์มแวร์ใหม่ (ครั้งแรกใช้เวลาคอมไพล์ ~4.5 นาที)
  - แท่นในสนามต่างจากในห้อง: แค่ขันน็อตยึดจานล้อต่างกัน ความเร็วก็ต่างกันประมาณ 3 เท่า
  - ไฟตกตอนมอเตอร์กระชาก (เช่นสั่งกลับทิศแรง ๆ) อาจทำให้บอร์ดรีเซ็ต ค่าที่จูนไว้ต้องไม่หาย
- **ความปลอดภัย:**
  - ค่าที่อยู่นอกช่วงที่กำหนดจะถูกปฏิเสธ ทั้งตอนสั่งและตอนโหลดจาก flash
  - ห้ามเปลี่ยนค่า sign ระหว่างโหมด AUTO

### 6. ชดเชย deadzone ของล้อ (F4)
- **ปัญหา:**
  - ตัวควบคุม PD สั่ง u = Kp·e − Kd·ω เมื่อใกล้เป้า u จะเล็กลงจนต่ำกว่า Min Stable
  - ล้อจึงไม่หมุน และระบบค้างห่างเป้าหลายองศา
- **ที่เราทำ:**
  - ถ้า `adcs.dzc = 1` คำสั่งที่อยู่นอก deadband จะถูกยกขึ้นพ้น deadzone ก่อน
  - ถ้าล้อหยุดอยู่ ยกให้เริ่มที่ Min Start (10 %) ถ้าล้อหมุนอยู่แล้ว ยกให้เริ่มที่ Min Stable (5 %)
  - ค่า 10 % และ 5 % มาจาก T01 ที่วัดเอง
- **หลักฐาน (จำลอง):** ของกรรมการค้างห่างเป้า 3.8–6.8° (ผลแบบใช้ dzc จะเพิ่มหลังทดสอบ)

### 7. ค่า gyro bias และทิศของ gyro ปรับได้
- gyro แต่ละตัวมี bias ไม่เท่ากัน และทิศต้องตรงกับทิศหมุนของตัวยาน
- **หลักฐาน (จำลอง):** ถ้าใส่ทิศผิด ระบบแกว่งหรือหมุนหนีเป้า (runaway) จึงต้องตั้งค่าได้โดยไม่ต้องอัปใหม่

## ข้อจำกัดที่ยอมรับตรง ๆ
- ข้อ 2–7 ทดสอบในโปรแกรมจำลองทั้งระบบแล้ว (49 รายการผ่าน, เทียบโมเดลมุมกับเว็บ 2007 กรณี) **แต่ยังไม่ได้ลองบนบอร์ดจริง**
- ข้อ 1 ทดสอบบนบอร์ดจริงแล้ว
- ตัวเลขฟิสิกส์ในโปรแกรมจำลองเป็นค่าประมาณ ต้องแทนด้วยค่าจริงจาก T01 และการ calibrate
